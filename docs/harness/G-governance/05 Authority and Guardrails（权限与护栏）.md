# 权限与护栏（Authority and Guardrails）

> 当前成熟度层级：`L3 可指导实现的治理规格层`
> 编码门槛：`已达到 L3，可直接指导第一批实现、接口设计与最小验证`

本文件用于展开治理层总览中的“确认、裁决与护栏”，集中保存确认机制、裁决权、角色权限边界、治理回执与设计禁令。

## 确认机制

G 层中的确认不是礼貌性交互，而是事实门禁。

确认至少要覆盖：

- 这次动作会改变什么
- 为什么被判为高风险
- 会影响哪些下游对象
- 用户是在批准、拒绝还是要求改写

## 裁决权模型

建议定义如下权力关系：

- agent：建议权
- 系统治理层：分类权
- 用户：裁决权
- 发布层：生效权

也就是说，agent 不能直接越过治理层取得发布权。

## 多角色对抗中的权限边界

当 EvoCanvas 启用发散者-收敛者-裁判者模式时，治理层必须进一步约束三者权限。

### 发散者的治理边界

发散者可以：

- 打开问题
- 暴露冲突
- 提出候选分支
- 提出需要补证据的点

发散者不可以：

- 关闭待澄清项（clarification）
- 将内容标记为已确认 / 已生效（confirmed / effective）
- 直接发布交接物（handoff）

### 收敛者的治理边界

收敛者可以：

- 形成结构化提案（proposal）
- 做候选归并
- 形成最小可推进结构

收敛者不可以：

- 删除关键未决冲突
- 直接把提案（proposal）升为稳定事实（stable truth）
- 用压缩摘要掩盖来源断裂

### 裁判者的治理边界

裁判者可以：

- 判定提案（proposal）是否进入下一步
- 判定是否需要更多证据
- 判定是否应回退到待澄清阶段（clarification）
- 判定是否必须触发确认

裁判者不可以：

- 自己增写新的事实内容
- 偷偷替收敛者完成对象生成
- 越过确认直接让高风险对象生效

### 三角模式下的生效规则

即使在多角色编排中，生效权也不能旁路治理层。

规则保持不变：

- 发散结果默认不是事实
- 收敛结果默认只是提案（proposal）
- 裁判结果默认只是分类和门禁判断
- 真正生效仍取决于验证与确认条件

## 治理回执

每次高风险动作都应留下清晰回执，至少包括：

- action type
- affected objects
- risk level
- triggered rule
- confirmation result
- resulting state

对于三角模式，还应补充：

- 当前是哪一角色输出触发了高风险判断
- 为什么另一角色的输出未被采纳

## 设计禁令

- 不允许把提案（proposal）当作事实层对象
- 不允许在高风险动作上默认自动通过
- 不允许冲突静默沉入系统
- 不允许未确认对象伪装成已确认对象
- 不允许正式交接物（formal handoff）掩盖关键未知项
- 不允许发散者和收敛者绕过裁判形成事实共谋
- 不允许裁判者同时兼任内容生成者与事实批准者

## 1.0 最小落地要求

EvoCanvas 1.0 的 G 层至少应具备：

- 事实分层
- 风险分级
- 冲突显性化
- 高风险确认门禁
- 生效条件规则
- 治理回执
- 多角色模式下的角色权限边界
