# Diagnostic Views（诊断视角）

> 方法成熟度：`L3 可指导实现的治理规格层`
> 目标实现归属：`EvoCanvas 只读诊断查询`
> 当前实现状态：`原生诊断视角已接入，故障样本待补齐`
> 实现说明：诊断视图从 Pi Trace、Revision 审计和投影检查点聚合，不创建新事实状态。

## 1. 控制目标

让产品、工程和支持人员按故障类型快速定位权威记录，而不是阅读混合日志猜测。

## 2. 必需视图

| 视图 | 回答 |
| --- | --- |
| 输入与上下文 | Pi 收到哪个 User Entry、使用哪个 Revision 和来源 |
| 指令与 Skill | 本轮固定了哪些版本、是否加载失败 |
| 工具与权限 | 调用了什么、身份与确认如何判定、实际结果是什么 |
| 稳定变更 | 哪些操作生成哪个 Revision、哪些依赖需复核 |
| 交接 | 当前与最近有效确认版本是什么、为何暂停或失效 |
| 投影 | Canvas 显示哪个 Revision、是否落后、重建是否成功 |
| 恢复 | 取消、重试、幂等查询和结果未知如何处理 |

## 3. 查询输入输出

查询至少接受 `workspace_id`，并可按 `submission_id / session_id / entry_id / invocation_id / operation_id / commit_id / revision_id / object_id / handoff_id / projection_id` 过滤。输出必须显示来源系统、时间、关联标识和权威级别。

## 4. 权限与隐私

默认用户只能查看自己有权访问 Workspace 的产品级诊断；完整 Prompt、来源正文、敏感工具参数和系统级错误仅向授权角色开放。诊断查询本身留审计记录。

## 5. 差异与矛盾

视图遇到层间不一致时不得强行合并：例如 Revision 已成功而 Projection 失败，应并列显示。自然语言解释可生成，但底层状态和链接必须来自确定性记录。

## 6. 失败与恢复

- 索引缺失：直接查询权威记录或触发索引重建。
- 部分系统不可用：显示已获取部分及缺失来源，不返回统一“未发生”。
- 访问被拒：不泄露目标是否存在。
- 时间顺序漂移：优先使用关联键和各系统序列，不只按墙钟排序。

## 7. 验收场景

1. 输入 Revision ID 可找到提交、确认、来源和投影。
2. 投影故障时视图明确区分业务提交成功与 Canvas 失败。
3. 未授权用户无法通过诊断接口读取来源正文。
4. 关联索引丢失后，重建不修改任何 Revision 或 Session Entry。
5. 多系统时间戳乱序时仍能依靠关联关系恢复实际因果链。
