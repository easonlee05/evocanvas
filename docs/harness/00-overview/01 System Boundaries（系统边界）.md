# System Boundaries（系统边界）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

本文档回答 EvoCanvas 1.0 的 harness 系统边界：

- 哪些能力属于 1.0 必须控制的主路径。
- 哪些能力可以保留为后续版本预留。
- 哪些旧产品语义不应继续扩展。

进一步说，它回答的是：这套 harness 到底在为哪类产品行为兜底，而不是泛泛定义“agent 能做什么”。

## 2. 1.0 必须服务的主路径

EvoCanvas 1.0 只验证一个最小闭环：

```md
输入编译 -> 待澄清问题 -> 约束 / 待决策 -> 结构化交接物
```

这条主路径要服务外层体验旅程：

```md
感觉接入 -> 对话塑形 -> 结构收敛 -> 画布显影 -> 结构化交接
```

对应的系统任务是：

- 接住尚未成形的感觉和多源输入。
- 接住多源原始输入。
- 帮助用户命名、拆解和追问，而不是急于产出结论。
- 抽取并组织结构化提案。
- 显性化冲突、缺口和未决问题。
- 在合适时机沉淀约束、待决策和结构化交接物。

## 3. 1.0 不做什么

Harness 设计不应把以下能力误认为当前必须范围：

- 完整传统 PRD 自动生成。
- 自由白板创作。
- 多人实时协作。
- 复杂项目管理系统。
- 全自动方案裁决。
- 把下游 AI 工具纳入 EvoCanvas 内部收敛流程。

这些能力即使未来可能成立，也不应反向主导 1.0 的 harness 结构。

同样，系统也不应把“先生成一份看起来完整的答案”误当成当前主目标。

## 4. 与旧产品语义的边界

迁移过程中，可以复用 Evoloop 的通用基础设施，但不应继续扩展旧产品面：

- `manual`
- `prd generator`
- `spec_to_agent`
- `acceptance_review`
- `任务大厅`
- `法则审核`

如果某些后端能力仍带旧命名，应优先判断它是通用基础设施、旧流程适配层，还是应逐步移除的遗留对象。

## 5. 判断某项能力是否属于 1.0 主路径的标准

如果一项能力不能直接提升“多源输入收敛为可交接上下文”的效率或可靠性，则默认不纳入 1.0 主路径。

更具体地说，它至少应满足以下之一：

1. 帮助接住感觉或输入，并保持可追溯。
2. 帮助命名、拆解、追问，推动对话塑形。
3. 帮助暴露不确定性、冲突或缺口。
4. 帮助沉淀约束、待决策或结构化交接物。
5. 帮助控制生效、验证、回执或治理过程。
