## 2. 模块定位

挂件模块是 EvoCanvas 工作台中的辅助层。

它不承载正式业务事实本身，而是为产品经理和后续 AI 协作提供：

1. 当前状态的投影视图。
2. 推进位置的辅助感知。
3. 临时思考的轻量承接容器。
4. 不打断主画布结构的桌面化工作工具。

挂件与卡片的边界必须明确：

1. `卡片` 是正式结构化状态的产品投影：前五类回指业务对象，交接物承接卡回指结构化包版本。
2. `系统挂件` 是系统生成的辅助视图，必须回指卡片、里程碑或状态计算结果。
3. `个人挂件` 是用户工作台工具，默认不进入正式对象层，且 1.0 不与卡片层打通。

---

## 3. 模块目标

挂件模块在 EvoCanvas 1.0 中要实现的目标不是“堆叠小工具”，而是让工作台更接近真实产品经理的桌面工作状态。

具体目标包括：

1. 让用户在不离开主画布的前提下，看见当前最重要的推进信号。
2. 让系统级投影视图与正式卡片层解耦，但保持可回溯。
3. 让用户能保留临时想法、待会再看事项和专注节奏，而不污染正式对象层。
4. 让挂件具备统一的工作台交互协议，避免每个挂件像独立产品一样分裂生长。

## 4. 模块范围

### 4.1 1.0 首版必须范围

1. 系统挂件：项目时间轴。
2. 系统挂件：活跃缺口（Active Todos）。
3. 挂件通用交互协议：移动、pin、折叠、关闭、位置持久化。
4. 个人挂件预留定义：便签、停车区、时钟、专注计时器。

### 4.2 1.0 首版预留但不强制实现范围

1. 便签挂件。
2. 停车区挂件。
3. 时钟挂件。
4. 专注计时器挂件。

这些挂件在 1.0 中先建立明确语义和交互边界，允许前端按节奏逐步实现，但不进入首版闭环验收硬门槛。

### 4.3 不在本模块范围

1. 把挂件做成新的事实源。
2. 把活跃缺口做成任务管理系统。
3. 把项目时间轴做成完整排期系统。
4. 把个人挂件自动写入结构化交接物。
5. 多个 AI 或多人在同一挂件内实时协同编辑。

## 5. 挂件通用规则

### 5.1 功能说明

所有挂件都应遵循统一的工作台交互协议，以保证用户形成稳定心智，而不是为每个挂件单独学习一套操作。

### 5.2 通用交互协议

所有挂件默认支持以下能力：

1. `移动`
   用户可将挂件在画布工作区内自由拖拽。
2. `pin / unpin`
   挂件可固定在默认锚点位置，也可取消固定后进入漂移态。
3. `折叠 / 展开`
   挂件可在不关闭的情况下缩成轻量条或轻量胶囊。
4. `关闭 / 再次打开`
   用户可临时关闭挂件，并通过统一入口再次打开。
5. `状态持久化`
   系统需持久化挂件的位置、折叠状态和 pin 状态。
6. `入口管理`
   底部工具栏必须提供挂件统一入口，用于打开挂件面板并添加组件。

### 5.3 通用展示字段

每个挂件至少应具备以下基础字段：

| 字段名称 | 说明 |
| --- | --- |
| 挂件 ID | 当前挂件实例唯一标识 |
| 挂件类型 | 系统挂件 / 个人挂件 |
| 挂件子类型 | 项目时间轴 / 活跃缺口 / 便签 / 停车区 / 时钟 / 专注计时器 |
| 标题 | 当前挂件标题 |
| 展示状态 | 钉住 / 漂移 / 折叠 / 关闭 |
| 默认锚点 | 挂件默认固定位置 |
| 漂移坐标 | 当前自由摆放位置 |
| 更新时间 | 最近一次状态更新时间 |

### 5.4 挂件入口要求

挂件不能依赖“用户记住它现在藏在哪”来使用，因此必须提供统一入口。

入口要求如下：

1. 入口位于底部工具栏，与选择、卡片、连线、文本等工作台基础操作并列。
2. 入口点击后应打开挂件面板，而不是直接创建新的事实对象。
3. 面板只负责 `展示可添加挂件 + 添加组件`，不负责挂件运行态管理。
4. 面板中的每个挂件项应提供明确的 `添加` 主动作。
5. 已添加挂件的 pin、折叠、关闭、拖动等操作应放在组件本体上，而不是放在入口面板里。

入口的交互分层应保持如下结构：

1. `底部工具栏`
   提供一级入口按钮，风格应接近 Figma 式工作台工具位，而不是“更多”菜单。
2. `挂件面板`
   作为轻量添加浮层存在，负责展示可添加挂件。
3. `组件本体`
   负责运行态控制，包括 pin、折叠、关闭和拖动。

1.0 的挂件面板应保持轻量：

1. 不要求搜索框。
2. 不要求 Tab 分类。
3. 不要求筛选器。
4. 不展示“已显示”“已钉住”“已隐藏”等运行态状态。
5. 每个挂件项只需要图标、名称、一句话说明和 `添加` 按钮。

### 5.5 通用视觉原则

1. 挂件要明显区别于正式卡片。
2. 挂件应呈现桌面化、悬浮化和轻工具化气质。
3. 挂件可有玻璃感、便签感、胶囊感等轻量视觉，但不能喧宾夺主。
4. 挂件的颜色与形态可按类型区分，但应共享统一框架。

### 5.6 与卡片的关系

1. 系统挂件只投影卡片和状态，不替代卡片。
2. 个人挂件中的内容默认不进入卡片层。
3. 个人挂件内容不进入正式推进链路。
4. 挂件内容不应被 AI 默认视为已确认业务事实。

## 6. 系统挂件

### 6.1 功能定位

系统挂件是由系统根据当前工作区状态投影出来的辅助视图。

它们的目标是：

1. 让用户看清“现在最该处理什么”。
2. 让用户看清“现在大致推进到哪里”。
3. 让系统状态辅助不打断主画布栏目结构。

### 6.2 系统挂件共性要求

1. 必须有明确上游来源。
2. 折叠、拖拽和 pin 仅影响展示，不影响底层数据。
3. 内容变化应与卡片、里程碑或状态计算结果保持同步。
4. 不应允许用户在系统挂件中直接创建脱离源对象的正式事实。
5. 系统挂件应能通过底部工具栏中的挂件入口被再次添加或重新唤起。

### 6.3 项目时间轴

#### 6.3.1 功能说明

项目时间轴用于向用户表达当前主题的大致推进位置。

它解决的问题不是排期管理，而是：

1. 当前工作区大致推进到了哪个阶段。
2. 距离下一个可交付节点还差哪些关键缺口。
3. 当前挂在画布上的问题、约束和决策，大体处在什么推进语境下。

#### 6.3.2 页面布局要求

1. 默认锚点位于工作台左下角。
2. 钉住状态下以横向轻量悬浮条展示。
3. 折叠状态下收缩为极简胶囊，不遮挡主画布。
4. 取消钉住后，可作为漂移挂件在画布中自由摆放。

#### 6.3.3 页面字段与组件要求

| 字段名称 | 组件要求 | 说明 |
| --- | --- | --- |
| 标题 | Text | 默认显示“项目时间轴”或“项目里程碑” |
| 阶段标签 | Segmented Track | 展示当前阶段带 |
| 节点标签 | Tick / Badge | 展示示意性里程碑节点 |
| 当前位置 | Pointer | 标记当前推进点 |
| 折叠按钮 | Icon Button | 控制折叠与展开 |
| pin 按钮 | Icon Button | 控制固定与漂移 |

#### 6.3.4 核心交互

1. 用户可查看当前阶段和当前位置。
2. 用户可折叠或展开时间轴。
3. 用户可 pin / unpin 时间轴。
4. 用户可拖动未 pin 的时间轴。
5. 时间轴的运行态操作统一在组件头部完成。

#### 6.3.5 状态与异常展示

1. 当当前主题尚未形成明显推进阶段时，应展示“阶段尚在收敛中”。
2. 当里程碑信息不足时，应保留轻量空状态，不渲染假精确时间。
3. 挂件的展示状态变化不应影响底层画布状态。

#### 6.3.6 验收标准

1. 用户能快速看见当前大致推进位置。
2. 用户不会将其误解为完整项目管理工具。
3. 它能以挂件形态存在，而不破坏主画布阅读。

### 6.4 活跃缺口（Active Todos）

#### 6.4.1 功能说明

活跃缺口挂件用于投影当前仍在阻塞推进的缺口。

它回答的问题是：

1. 当前最应该优先处理的缺口是什么。
2. 哪些缺口在阻塞约束沉淀、待决策收束或交接推进。
3. 哪些事项已经形成明确动作但仍未关闭。

#### 6.4.2 页面布局要求

1. 默认锚点位于工作台右上角。
2. 钉住状态下以竖向悬浮看板展示。
3. 折叠状态下收缩为轻量胶囊，只显示标题与数量。
4. 取消钉住后，可作为漂移挂件在画布中自由摆放。

#### 6.4.3 页面字段与组件要求

| 字段名称 | 组件要求 | 说明 |
| --- | --- | --- |
| 标题 | Text | 默认显示“活跃缺口” |
| 活跃总数 | Badge | 当前活跃条目数量 |
| 类型分组 | Section Header | 待澄清 / 待定义 / 待决策 |
| 条目列表 | List | 当前投影出的活跃缺口 |
| 源卡跳转 | Jump Link | 点击后回到源卡 |
| 折叠按钮 | Icon Button | 控制折叠与展开 |
| pin 按钮 | Icon Button | 控制固定与漂移 |

#### 6.4.4 核心交互

1. 用户点击条目后可定位到源卡。
2. 用户可在 AI 对话中围绕该缺口继续推进。
3. 用户可折叠、pin / unpin 和拖动该挂件。
4. 活跃缺口的运行态操作统一在组件头部完成。

#### 6.4.5 状态与异常展示

1. 当无活跃缺口时，应展示“当前没有活跃缺口”。
2. 当源卡失效时，对应条目应同步失效。
3. 当多个条目来自同一缺口时，应支持合并投影。
4. 挂件的移动和折叠状态不应改变条目内容。

#### 6.4.6 验收标准

1. 条目只来自允许的源对象。
2. 每条条目都能回到源卡。
3. 用户可快速区分当前优先级高低。
4. 挂件不会被误解为任务管理系统。

## 7. 个人挂件

### 7.1 功能定位

个人挂件用于承接用户在真实工作中的“桌面动作”，包括临时记忆、短期提醒、节奏控制和暂缓展开事项。

它们不解决正式业务沉淀，而解决以下问题：

1. 一些想法现在不该进入正式对象层，但又不能丢。
2. 一些事项只是当前工作习惯或节奏控制，不该污染主画布。
3. 用户需要更像工作台而不是纯结构化工具的空间感。

### 7.2 通用规则

1. 个人挂件默认不进入结构化交接物。
2. 个人挂件默认不参与关系计算。
3. 个人挂件默认不触发 Active Todos 投影。
4. 个人挂件后续落地时，应通过统一挂件入口添加，但其运行态控制仍在组件本体上完成。

### 7.3 便签

#### 7.3.1 功能说明

便签用于记录一句话判断、提醒、问题或灵感。

它适合承接以下内容：

1. 还没想清楚的一句话。
2. 暂时不想打断主线但必须记住的点。
3. 未来可能转成卡片的候选内容。

#### 7.3.2 页面布局要求

1. 便签默认以小尺寸贴纸式挂件展示。
2. 支持多张便签并存。
3. 未 pin 时可自由散落摆放，形成桌面感。

#### 7.3.3 页面字段与组件要求

| 字段名称 | 组件要求 | 说明 |
| --- | --- | --- |
| 标题 | Optional Text | 可选，默认允许无标题 |
| 正文 | Multiline Text | 便签主内容 |
| 颜色 | Theme Token | 区分不同便签语义或仅作视觉区分 |
| 创建时间 | Text | 便签建立时间 |

#### 7.3.4 核心交互

1. 用户可快速新建便签。
2. 用户可编辑文本。
3. 用户可拖动、pin、折叠、关闭便签。

#### 7.3.5 状态与异常展示

1. 空便签关闭时可直接丢弃。
2. 便签过多时，应允许轻量堆叠或缩略，不应挤爆画布。

#### 7.3.6 验收标准

1. 用户能用便签承接临时想法而不污染卡片层。
2. 便签内容不进入结构化交接物。

### 7.4 停车区（Parking Lot）

#### 7.4.1 功能说明

停车区用于放置“现在先不展开，但以后要回来处理”的事项。

它适合承接：

1. 当前讨论的旁支问题。
2. 暂缓进入 1.0 范围的点子。
3. 会打断主收敛链路但又不能彻底遗忘的事项。

#### 7.4.2 页面布局要求

1. 停车区默认是一个列表式或堆叠式容器挂件。
2. 它比便签更容器化，强调“先停在这里”。
3. 可长期 pin 在工作区一侧，也可自由漂移。

#### 7.4.3 页面字段与组件要求

| 字段名称 | 组件要求 | 说明 |
| --- | --- | --- |
| 标题 | Text | 默认显示“停车区” |
| 条目列表 | List | 当前被暂缓的事项 |
| 条目状态 | Badge | 暂放中 / 准备恢复 |
| 恢复处理按钮 | Action Button | 把某条事项重新拉回当前工作流 |

#### 7.4.4 核心交互

1. 用户可新增停车区条目。
2. 用户可调整条目顺序。
3. 用户可将某条内容恢复到主线处理。

#### 7.4.5 状态与异常展示

1. 停车区为空时，应展示“当前无暂缓事项”。
2. 停车区条目过多时，应支持折叠和滚动。
3. 停车区条目不应自动进入活跃缺口。

#### 7.4.6 验收标准

1. 用户能把暂不展开的内容可靠存放。
2. 停车区不会被误解为正式待办系统。
3. 条目回到主线时必须通过显式动作。

### 7.5 时钟

#### 7.5.1 功能说明

时钟用于给工作台提供环境感知，而不是业务事实承接。

它解决的问题包括：

1. 当前时间感知。
2. 跨时区协作中的快速时间确认。
3. 长时间画布工作中的轻量环境提示。

#### 7.5.2 页面布局要求

1. 默认以小尺寸信息挂件展示。
2. 可支持单时区或双时区。
3. 应尽量克制，避免抢占主画布注意力。

#### 7.5.3 页面字段与组件要求

| 字段名称 | 组件要求 | 说明 |
| --- | --- | --- |
| 当前时间 | Text | 本地时间 |
| 时区标签 | Badge / Text | 如北京时间、UTC 等 |
| 第二时区 | Optional Text | 可选展示第二时区 |
| 24h / 12h 切换 | Optional Toggle | 显示格式切换 |

#### 7.5.4 核心交互

1. 用户可移动、pin、折叠、关闭时钟。
2. 用户可切换显示格式。
3. 用户可配置第二时区。

#### 7.5.5 状态与异常展示

1. 时间获取失败时，应保底显示本地系统时间或空状态提示。
2. 时钟不应依赖网络才能基础可用。

#### 7.5.6 验收标准

1. 时钟作为纯环境挂件成立。
2. 它不进入正式对象层。
3. 它在视觉上足够轻，不干扰主画布。

### 7.6 专注计时器

#### 7.6.1 功能说明

专注计时器用于辅助用户以阶段化节奏推进收敛工作。

它适合以下场景：

1. 给自己 15 分钟专门收敛待澄清。
2. 给自己 20 分钟整理交接物。
3. 在会前或会后设置一个短时推进窗口。

#### 7.6.2 页面布局要求

1. 默认以小尺寸仪表或数字倒计时挂件展示。
2. 折叠时只保留剩余时间和状态。
3. 展开时可显示预设时长、当前模式和完成状态。

#### 7.6.3 页面字段与组件要求

| 字段名称 | 组件要求 | 说明 |
| --- | --- | --- |
| 剩余时间 | Numeric Display | 当前倒计时 |
| 模式标签 | Badge | 收敛 / 整理 / 交接 等 |
| 开始 / 暂停按钮 | Action Button | 控制计时状态 |
| 重置按钮 | Action Button | 恢复预设 |
| 预设时长 | Select | 15 / 20 / 25 分钟等 |

#### 7.6.4 核心交互

1. 用户可开始、暂停和重置计时。
2. 用户可切换预设时长。
3. 用户可移动、pin、折叠和关闭挂件。

#### 7.6.5 状态与异常展示

1. 倒计时结束时，应给出轻量提示，不应打断主画布操作。
2. 计时暂停后，应保留当前剩余时间。
3. 计时器状态不应触发任何正式对象变更。

#### 7.6.6 验收标准

1. 用户能用它控制短时专注节奏。
2. 它不会被误解为项目计划工具。
3. 它不进入正式事实层，也不自动驱动业务状态变化。

---

## 8. 个人挂件与正式对象层边界

### 8.1 边界原则

1. 个人挂件在 1.0 中不进入卡片层。
2. 个人挂件在 1.0 中不进入结构化交接物。
3. 个人挂件在 1.0 中不参与关系计算和状态流转。

### 8.2 不允许的自动化

以下行为在 1.0 中不允许自动发生：

1. 系统自动把便签提升为约束。
2. 系统自动把停车区条目写成待决策。
3. 系统自动把个人挂件内容写入交接物。

---

## 9. 状态、异常与非功能要求

### 9.1 状态要求

挂件至少应支持：

1. 打开
2. 折叠
3. 钉住
4. 漂移
5. 关闭

### 9.2 异常要求

1. 挂件状态持久化失败时，不应影响主画布内容。
2. 挂件位置越界时，应自动拉回可视区域。
3. 挂件渲染失败时，应允许用户关闭或重置该挂件，而不破坏整个工作台。

### 9.3 非功能要求

1. 挂件交互必须轻量，不应明显拖慢画布拖拽和缩放。
2. 移动端或窄视口下，挂件应自动避让主操作区。
3. 挂件视觉层级需稳定，不应遮挡关键输入区和主卡片交互。

---

## 10. 验收标准汇总

### 10.1 系统挂件

1. 项目时间轴与活跃缺口具备统一挂件交互协议。
2. 两者都支持 pin / unpin、折叠与位置持久化。
3. 两者都不成为独立事实源。
4. 两者的运行态控制都在组件本体上完成。

### 10.2 个人挂件定义

1. 便签、停车区、时钟、专注计时器有清晰产品语义。
2. 每类挂件都能说明“它解决什么问题”与“它不做什么”。
3. 每类挂件都明确是否进入正式对象层。
4. 每类挂件都有明确的统一入口挂接方式，且入口只负责添加。

### 10.3 层级边界

1. 个人挂件内容不进入结构化交接物。
2. 个人挂件不参与正式对象链路。
3. 系统不会静默把个人挂件内容视为稳定业务结论。
