# Main Runtime Loop（运行主链）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

本文档描述 EvoCanvas harness 的主运行链路。

它不是普通聊天流程，而是从 `Vibe Shaping` 进入结构收敛的受控推进链路。

## 2. 最小推进链路

```md
感觉接入 / 输入接入
-> 对话塑形
-> 上下文装配
-> 提案生成
-> 验证
-> 安全与治理判定
-> 应用 / 挂起 / 拒绝
-> 状态账本与回执
```

## 3. 最小状态推进逻辑

EvoCanvas 的主状态机不是聊天状态机，而是收敛状态机。

最小流程可进一步理解为：

1. 感觉接入（vibe intake）：允许用户从一句话、一张图、一段聊天或零散表达开始。
2. 对话塑形（shaping）：帮助用户命名、拆解和追问，让模糊感觉先变成可讨论对象。
3. 输入编译（compilation）：提取来源片段、解释对象、问题和缺口。
4. 待澄清显影（clarification）：显性化冲突、未知项和待澄清。
5. 约束 / 决策收敛（constraint / decision convergence）：沉淀约束，形成待裁决事项。
6. 画布显影 / 结构化交接（projection / handoff）：把稳定结果映射为画布对象，并在需要时生成结构化交接物。

系统不要求所有问题都先被解决，才允许进入交接阶段；但必须把未决项显性带出。

## 4. 与产品阶段的映射

| 产品阶段 | Harness 责任 |
| --- | --- |
| 感觉接入 | 接住输入，保留原始表达，不急于定性 |
| 对话塑形 | 理解 vibe，帮助命名、拆解并形成关键追问 |
| 结构收敛 | 显性化待澄清、约束和待决策 |
| 画布显影 | 把稳定到可承载的对象映射为卡片、关系和缺口投影 |
| 结构化交接 | 打包已知、未知、已决和未决，并作为下游 AI 的可消费上下文 |

## 5. 运行主链的硬约束

- 模型输出默认只是提案，不直接写入事实层。
- 工具结果默认先进入来源和证据链，不直接成为结论。
- 高影响动作必须进入确认或治理流程。
- 每一轮结束后必须留下可读回执和可追溯痕迹。

## 6. 回流与停机条件

当出现以下情况时，系统应优先回流到澄清或治理，而不是继续压缩结论：

- 来源冲突尚未解释。
- 关键上下文缺失。
- 高影响动作未获确认。
- 验证未通过但模型仍试图继续推进。

换句话说，运行主链定义的是“流程怎么走”，不是“任何时候都要往前冲”。
