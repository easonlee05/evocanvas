# System Boundaries（系统边界）

> 方法成熟度：`L3 可指导实现的治理规格层`
> 目标实现归属：`全局架构边界`
> 当前实现状态：`目标合同已定，迁移未完成`
> 实现说明：边界以权威记录和控制权划分，不以当前进程或目录划分。

## 1. 控制目标

防止迁移时重新引入第二运行核心、第二事实源、第二确认流，或让 Canvas 与交接物获得不属于它们的裁决权。

## 2. 系统内边界

### 2.1 Pi Agent Core

拥有 Session、模型、Tool Loop、Skills、上下文变换、压缩、取消、重试和技术 Trace。它可以理解与建议，但不能替用户拥有产品判断。

### 2.2 EvoCanvas 产品能力

包括产品 Instructions / Skills、结构化工作包 Schema、读取与语义提交工具、确认和依赖规则、交接渲染、评估规则。这些能力装入 Pi 或消费 Pi 事件，不构成外部 Agent Kernel。

### 2.3 Canvas Renderer

只从稳定 Revision 生成卡片、关系、状态和辅助挂件。Canvas 交互若改变业务含义，必须转换成同一语义提交；纯布局不成为事实。

### 2.4 外部系统

文件、连接器、下游 Agent 和发布目标均通过工具接入。外部结果必须保留实际身份、权限、来源和回执。

## 3. 明确禁止

- Pi 外的 Product Kernel、Supervisor 或阶段路由器。
- 独立 Chat / 判断 / 收敛运行类型。
- 平行 Conversation History、上下文清单或状态账本。
- 工作包整份自由覆写。
- 未确认候选生成正式 Canvas 卡片。
- 交接物正文作为独立可编辑事实源。
- 用模型“置信度”自动跨过用户确认。
- 将实现迁移兼容字段反向写成目标架构。

## 4. 产品范围边界

Harness 服务 `感觉接入 -> 对话塑形 -> 结构收敛 -> 画布显影 -> 结构化交接`。它不扩展 EvoCanvas 为自由白板、完整项目管理、多人实时协作或复杂交付编排系统。

## 5. 权限边界

| 动作 | 最终控制者 |
| --- | --- |
| 对话和候选分析 | Pi，在用户权限范围内 |
| 产品含义和范围固定 | 用户 |
| Schema、版本、状态和幂等校验 | 确定性工具 |
| 交接可用性和风险接受 | 用户 + 工具门禁 |
| 外部不可逆动作 | 用户动作级授权 + 对应工具 |
| Canvas 显影 | Renderer，根据 Revision |

## 6. 失败与恢复

任一子系统故障时不改变其他子系统的权威性。Pi 故障不删除 Revision；工作包故障时关闭稳定写入；Canvas 故障从 Revision 重建；外部工具故障以外部回执和幂等查询核对。

## 7. 验收场景

1. 现有代码保留旧字段时，目标路径不能继续产生旧语义运行记录。
2. Canvas 缓存丢失不会导致稳定业务状态丢失。
3. Pi Session 故障时工作包仍可只读，但不能伪造过程来源。
4. 交接 confirmed 不能直接授权外部发布。
5. 用户在 Canvas 连线时仍经过语义关系提交和权限门禁。
