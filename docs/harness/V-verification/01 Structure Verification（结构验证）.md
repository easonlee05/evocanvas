# 结构验证（Structure Verification）

## 1. 结构验证回答什么

结构验证只回答一个问题：

`这个对象在形式上能不能成立`

它不判断这个对象是否真实，也不判断它是否应该生效。

## 2. 结构验证的默认检查范围

结构验证至少检查以下四类内容：

- 类型是否合法
- 必填信息是否齐全
- 引用是否存在且可指向
- 当前状态或层级是否允许

因此，结构验证的目标不是追求字段越多越好，而是先守住“最小可成立对象”。

## 3. 结构验证的最小规则

对 EvoCanvas 1.0，结构验证至少应覆盖：

- 结构化对象必须带有明确对象类型
- 引用型对象必须能回指上游对象或来源片段
- 准备进入正式交接的对象必须能回指当前主题语境
- 准备触发高影响动作的对象不得缺关键字段

对象结构不成立时，默认不得继续升格。

## 4. 对关键对象的结构要求

来源片段（source fragment）至少要能表达：

- 来源归属
- 摘录内容
- 与当前主题的关联

解释对象（interpretation）至少要能表达：

- 当前核心判断
- 关联来源片段
- 当前稳定度或不确定性说明

待澄清项（clarification）至少要能表达：

- 问题本身
- 为什么要问
- 不回答会阻塞或污染什么

约束（constraint）至少要能表达：

- 边界内容
- 依据
- 影响范围

待决策候选（decision candidate）至少要能表达：

- 当前要拍板什么
- 候选项或方向
- 推荐与影响

结构化交接物（structured handoff）至少要能表达：

- 当前主题
- 已确认内容
- 高置信但未确认内容
- 仍存未决

## 5. 结构验证与挂载关系

结构验证是 V 层默认最先执行的一层检查。

只要结构不成立：

- 不继续进入来源验证
- 不继续进入策略验证
- 不把对象提交到正式交接或正式生效位

这不是因为结构比真实性更重要，而是因为连对象边界都不成立时，后续验证会失去承载面。
