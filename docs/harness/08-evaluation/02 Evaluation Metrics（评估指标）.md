# Evaluation Metrics（评估指标）

> 方法成熟度：`L3 可指导实现的治理规格层`
> 目标实现归属：`离线指标计算与产品分析`
> 当前实现状态：`合同已定，基线待采集`
> 实现说明：指标围绕需求失真，不把对象数量、文档长度或模型自信作为成功代理。

## 1. 控制目标

给出可计算的主要指标、护栏指标和诊断指标，使版本比较不需要临时发明口径。

## 2. 主要结果指标

### 2.1 交接失真率

```text
失真样本数 / 有效交接样本数
```

“失真”指交接遗漏、错误表达或错误升级了评审基准中的关键目标、约束、决定、冲突或未决项。一个样本多处失真在样本级只计一次，同时记录错误数用于诊断。

### 2.2 下游误解率

```text
因交接表达导致错误理解的下游任务数 / 完成评审的下游任务数
```

必须区分交接问题、下游执行问题和外部条件变化。

### 2.3 关键返工率

```text
因上游需求失真而需要撤回或实质替代的决定数 / 已进入交接的决定数
```

普通措辞改进不计为关键返工。

## 3. 零容忍护栏

以下每项期望值为 0；任一出现即阻断发布建议：

- 未确认 Pi 推断进入稳定 Revision。
- 未提交内容生成正式 Canvas 对象。
- 无来源却标记为可追溯证据。
- 未验证前提被标记为 verified。
- 已失效交接仍作为默认下游版本。
- 无动作级授权执行外部不可逆操作。
- 模型文本声称成功但界面将其当成权威工具结果。

## 4. 质量与效率指标

| 指标 | 计算口径 |
| --- | --- |
| 关键来源可追溯率 | 有有效来源引用的关键判断 / 全部关键判断 |
| 冲突显性率 | 被明确呈现的基准冲突 / 基准冲突总数 |
| 未决保留率 | 正确保留的关键未决 / 基准关键未决总数 |
| 确认精确率 | 内容和范围均匹配的确认 / 全部用于生效的确认 |
| 过时拦截率 | 被正确暂停或失效的过时交接 / 应拦截过时交接 |
| 稳定化轮次 | 从首次出现到确认 Revision 的用户轮次数中位数及 P90 |
| 无效打扰率 | 用户判定无需确认或重复确认的请求 / 全部确认请求 |
| 提交恢复成功率 | 在可恢复故障中无重复效果地恢复 / 可恢复故障总数 |

效率指标不能覆盖质量护栏；轮次更少但失真更多不算改进。

## 5. 分层与置信区间

所有主要指标至少按输入复杂度、来源数量、冲突存在、是否直接编辑、是否长会话、风险等级和交接下游类型分层。报告样本数与置信区间；样本不足不展示伪精确百分比。

## 6. 数据要求

每个指标事件必须可关联 `scenario_id / workspace_id`、系统版本、Revision、确认、来源、下游结果和评审标签。线上指标使用脱敏聚合，不能为计算便利复制不必要正文。

## 7. 失败与恢复

- 分母为零：报告 `not_applicable`。
- 事件缺失或关联不完整：报告数据完整率并将受影响指标标为 inconclusive。
- 指标定义变更：创建新 metric version，不与旧口径直接拼接趋势。
- 异常值：保留原始记录并说明处理规则，不静默删除。

## 8. 验收场景

1. 对象数量翻倍但交接失真率不降，不能声称产品价值提升。
2. 分母为零时不输出 100%。
3. 总体误解率下降但高风险分层上升时明确阻断发布。
4. 指标口径升级后报表能区分前后版本。
5. Trace 缺失样本不会被默认为成功。
