# 独立评估（Independent Evaluation）

## 1. 独立评估回答什么

独立评估回答的是：

`在前三类验证之外，这个高价值结果是否还需要额外再看一层`

它不是默认必经层，而是对高价值、高影响或高歧义结果的补充检查。

## 2. 独立评估的启用条件

以下情况默认值得启用独立评估：

- 准备进入正式结构化交接物（formal handoff）
- 准备触发高影响动作
- 当前结果虽然通过基础验证，但仍存在较高歧义
- 当前结果会被多个下游对象长期依赖

对于低风险、低歧义结果，不应把独立评估泛化成每步必过的额外成本。

## 3. 独立评估的默认职责

独立评估主要补看三类问题：

- 基础验证是否遗漏了关键冲突或关键缺口
- 当前收敛是否过早
- 当前交接或高影响结果是否会误导下游继续推进

它可以采用：

- 额外规则校验
- 独立评估者（evaluator）
- 用户确认前的额外复核

对 EvoCanvas 1.0，推荐从“规则补检 + 必要时人工 / 用户确认”起步，而不是一开始把独立模型评审做成默认主链。

## 4. 独立评估与前三类验证的关系

独立评估不能替代：

- 结构验证
- 来源验证
- 策略验证

也就是说：

- 结构不成立，不能直接跳到独立评估补救
- 来源断裂，不能指望独立评估替它洗白
- 策略跳步，不能靠“再评一次”变成合法推进

独立评估只在前三类验证已经跑完后，补充做高价值复核。

## 5. 独立评估的最小输出

独立评估至少应输出：

- 是否通过额外复核
- 额外复核关注了什么
- 是否发现新的关键风险或冲突
- 是否建议进入治理放行判断、继续披露风险，或转回更保守层级

这些内容最终仍应以验证回执形式回到 V 层总闭环，再交给 L 层与 G 层继续处理。
