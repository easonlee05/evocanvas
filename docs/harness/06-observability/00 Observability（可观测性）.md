# Observability（可观测性）

> 当前成熟度层级：`L2 对象与流程定义层`
> 编码门槛：`未达到 L3；可作为 trace、显影提示和诊断字段的设计输入`

## 1. 这一层回答什么问题

可观测性回答：EvoCanvas 每一轮到底推进了什么，为什么这样推进，哪些内容被应用、降级、拒绝、判定过期或回流。

它不是“多打日志”，而是让 `Vibe Shaping` 的状态变化可见、可回看、可归因。

用户不应该只看到一串聊天记录，而应该能回答：

- 这次讨论消除了哪些不确定性。
- 新增或更新了哪些卡片。
- 哪些信息地位升级因为确认不足而保持候选或未决。
- 当前还剩哪些活跃缺口。
- 结构化交接物为什么已经可用，或为什么仍不能确认。

## 2. 观察对象

EvoCanvas 1.0 的可观测性围绕五类对象展开：

1. 回合（turn）：一轮输入、Chat、判断、提案、验证和提交或正常结束的运行过程。
2. 状态变化（state diff）：卡片、关系、Todo、里程碑和交接物发生了什么变化。
3. 显影提示（projection signal）：收敛回合实际改变画布时的低打扰提示，见 [Projection Signals（显影提示）](./01%20Projection%20Signals%EF%BC%88%E6%98%BE%E5%BD%B1%E6%8F%90%E7%A4%BA%EF%BC%89.md)。
4. 追踪模型（trace model）：给系统和工程诊断用的结构化记录，见 [Trace Model（追踪模型）](./02%20Trace%20Model%EF%BC%88%E8%BF%BD%E8%B8%AA%E6%A8%A1%E5%9E%8B%EF%BC%89.md)。
5. 诊断视角（diagnostic view）：当结果异常时如何定位问题，见 [Diagnostic Views（诊断视角）](./03%20Diagnostic%20Views%EF%BC%88%E8%AF%8A%E6%96%AD%E8%A7%86%E8%A7%92%EF%BC%89.md)。

这里真正要被看见的，不是模型“想了什么”，而是工作面发生了什么：

- 右侧 AI 助手里，这轮理解、追问、建议和用户确认原文是什么。
- 主画布里，哪些卡片、关系、冲突和状态被改变了。
- Active Todos 里，哪些活跃缺口被投影出来、哪些已经消失。
- 轻量里程碑条里，当前推进位置有没有发生变化。
- 交接物承接卡里，哪些依赖更新导致它进入待确认或已过时。

## 3. 与 PRD 工作面的关系

可观测性必须贴近 1.0 的真实工作面：

- 右侧 AI 助手通过正常 Chat 引导用户收敛；画布卡片与可选 Toast 显示已经发生的状态投影。
- 主画布通过卡片状态、关系和冲突提示展示当前结构。
- Active Todos 投影当前仍影响推进的活跃缺口，但不是独立事实源。
- 轻量里程碑条提示当前推进位置，但 1.0 不要求复杂历史版本回放。
- 结构化交接物需要记录依赖的约束、决策、未决问题和关键来源。

## 4. 设计原则

### 4.1 用户可读优先

用户需要的是“这轮到底变了什么”，不是模型内部推理链。

### 4.2 来源链可追溯

任何进入已生效、已决定或已确认状态的内容，都必须能追溯到来源、确认方式或用户裁决。

### 4.3 状态变化可审计

高影响信息地位升级、用户确认或撤回、对象过时和替代关系必须留痕。

### 4.4 诊断不污染工作面

工程诊断 trace 可以比用户回执更细，但不应把模型内部推理暴露为用户必须理解的产品内容。

### 4.5 当前状态优先，但不抹掉历史

1.0 的主工作面默认展示当前最新状态，而不是完整历史快照系统。

但这不意味着历史可以消失：

- 已替代约束要能看见替代关系。
- 已过时交接物要能知道为什么过时。
- 被关闭的待澄清要能保留关闭痕迹。
- 取消确认后的动作要能知道为什么没有落盘。

## 5. 最小落地要求

EvoCanvas 1.0 至少需要：

- 回合追踪（turn trace）。
- 状态差异记录（state diff）。
- 画布投影与可选显影提示（projection signal）。
- 高影响信息地位升级的确认记录。
- 来源链追踪（provenance trace）。
- 异常和回流记录。

这套可观测性不是为了做报表，而是为了让用户信任：当前画布不是 AI 随手写出来的，而是一步步收敛、确认和留痕形成的。
