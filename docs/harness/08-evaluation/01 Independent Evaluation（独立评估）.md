# Independent Evaluation（独立评估）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

独立评估回答：在基础验证已经跑过之后，某个高价值结果是否还值得再做一层独立复核。

它的目标不是增加流程感，而是降低”表面过关、实际误导下游”的风险。

它不是每一步都要做，也不是”换一个模型再评价一下”这么宽泛。

**两种用途：** 本文档承载两种不同的用途。§3–§4 的单次结果复核服务验证质量，确保高价值结果在确认前多过一层检查；§6 的跨样本聚合为产品命题判断提供证据。前者是在验证之后、确认之前的可选增强，不是并行的第二套验证器，也不能替代或绕过结构/来源/策略验证。

## 2. 什么时候值得启用

以下情况值得考虑启用独立评估：

- 结构化交接物准备被确认、外发，或继续派生为面向 AI 的 PRD。
- 当前结果虽然通过基础验证，但仍存在较高歧义。
- 某条约束或某个决策会被多个下游对象长期依赖。
- 系统连续出现交接物过时、返工、回流或反复冲突。
- 用户明确希望系统帮忙检查“有没有漏掉关键问题或关键边界”。

低风险、低歧义的小修订不应默认启用，否则会把工作台做成沉重审批流。

## 3. 复核重点

> **时序说明：** 以下复核在基础验证已通过之后运行，是**事后回顾性检查**，不是实时门禁。它不与结构/来源/策略验证并行，也不能代替它们。

独立评估主要看这些问题：

### 3.1 是否漏了关键缺口

- 还有没有真正会阻塞继续推进的问题，没有被放进待澄清或待决策。
- 当前 Active Todos 是否遗漏了会影响交接的活跃缺口。

### 3.2 是否过早稳定化

- 是否把 Chat 中尚未确认的约束提议写成约束卡或已确认内容。
- 是否把需要人拍板的事项写成已决定。
- 是否在关键冲突未解决时过早生成交接物。

### 3.3 是否会误导下游

- 下游同事或下游 AI 是否会把当前交接物误读成“已经完整定稿”。
- 交接物里是否明确说明了未解决问题、待确认决策和当前边界。
- 面向 AI 的 PRD 线索是否会让下游继续放大错误前提。

### 3.4 是否真的可以继续推进

- 如果把当前结果交给另一个产品同事，他是否能继续推进，而不是先回来追问基础背景。
- 如果后续立刻出现新输入，这个结果是否能稳定承接，还是会瞬间崩回未收敛状态。

## 4. 输出形式

独立评估至少应输出：

- 复核结论：通过、通过但有风险、不通过。
- 发现了什么关键问题或关键风险。
- 这些问题会影响哪里。
- 建议下一步动作。

建议动作通常包括：

- 继续确认
- 补澄清
- 补来源
- 显性化冲突
- 回到待决策
- 刷新交接物
- 保持草稿，不继续外发

## 5. 与验证的关系

独立评估不能替代结构验证、来源验证和策略验证。

- 结构不成立，不能靠独立评估补救。
- 来源断裂，不能靠独立评估洗白。
- 高影响信息地位升级缺确认，不能靠独立评估绕过用户。

它只是额外复核，不是特权通道。

## 6. 与产品评估的关系

独立评估既可以服务单次高价值结果，也可以为产品层评估提供样本。

例如：

- 多次独立评估都发现“系统总是把待决策写成结论”，说明 1.0 的收敛策略本身还有问题。
- 多次独立评估都发现“交接物虽然完整，但下游仍要回头补背景”，说明产品在交接可继续性上还没成立。

所以独立评估的价值，不只是拦一次风险，也是在帮助判断产品命题是否真的成立。
