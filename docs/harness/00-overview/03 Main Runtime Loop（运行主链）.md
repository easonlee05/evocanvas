# Main Runtime Loop（运行主链）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

本文档定义 EvoCanvas 如何把自然对话与结构化状态推进连接起来。

它不是把每一轮 Chat 都改造成对象写入流程。EvoCanvas 的主对话保持正常、主动的收敛式协作；只有当对话已经形成值得沉淀的理解时，系统才启动受控收敛回合。

## 2. 两类关联回合

### 2.1 Chat 回合

Chat 回合负责与用户共同推进理解：接住感觉、命名、比较候选方向、暴露冲突、追问关键缺口，并取得用户的自然语言确认。

它可以积极引导收敛，但不直接拥有结构化事实写入权。每一轮都保留原始 `user / assistant / tool` 消息；它不要求生成卡片、变化摘要或结构化包。

### 2.2 收敛回合

收敛回合是既有的受控推进链路。它只在后置判断命中后启动，负责把当前对话和已有对象整理为可验证、可治理的结构化提案。

```md
装配当前上下文
-> 生成结构化提案
-> 验证
-> 安全与治理判定
-> 应用 / 无变化 / 尚未准备好 / 治理拒绝 / 已过期
-> 原子更新结构化包、状态账本与 trace
-> 画布投影
```

收敛回合由 Chat 回合触发，但与其是独立的异步运行单元。

## 3. 后置判断与触发

Chat 回合结束后，系统先运行轻量判断，而不是立刻整理所有对话。

- 规则层负责硬边界和必然触发条件。
- 小模型负责判断当前对话是否形成了值得沉淀的理解、重要冲突、待决策或对象更新。
- 连续短消息可以合并为一次判断，避免把补充表达拆成多次无效收敛。
- 判断命中后只创建收敛回合；它不直接生成对象，也不拥有写入权。

这延续 [Convergence Confidence（收敛置信度）](./05%20Convergence%20Confidence%EF%BC%88%E6%94%B6%E6%95%9B%E7%BD%AE%E4%BF%A1%E5%BA%A6%EF%BC%89.md) 的混合判断原则：它回答“现在是否值得继续收敛”，不回答“内容是否已经生效”。

## 4. 产品旅程、收敛操作与投影动作

`感觉接入 -> 对话塑形 -> 结构收敛 -> 画布显影 -> 结构化交接` 是产品体验叙事，不是主题的持久化阶段状态机。

- 感觉接入、对话塑形和结构收敛，是同一收敛引擎在不同输入成熟度下执行的连续操作。
- 画布显影是结构化状态的投影动作，不是收敛阶段。
- 结构化交接是对当前状态的打包动作，不是收敛阶段。

系统不维护“当前主题正处于画布显影或结构化交接阶段”之类的状态。当前成熟度由对象、来源、冲突、未决和确认状态共同表达。

## 5. 画布与确认的分工

- Chat 是发现缺口、追问、比较和取得用户确认的主要交互面。
- 收敛回合在对话形成足够稳定理解后更新结构化状态。
- 画布只显影当前结构化状态，不承担频繁的确认流程，也不是事实来源。
- 高影响确认应在 Chat 中完成；确认后的状态变化再由收敛回合写入并投影到画布。

画布发生实际变化时，可以使用低打扰 Toast 提示“工作面已更新”。Toast 不是确认机制，也不替代 Chat；用户不应因每一次后台整理而收到固定回执卡或第二条助手消息。

## 6. 运行主链的硬约束

- 模型输出默认只是提案，不直接写入事实层。
- 工具结果默认先进入来源和证据链，不直接成为结论。
- 高影响信息地位升级必须经过用户在 Chat 中的确认和治理放行；草稿和候选整理不要求额外操作确认。
- Chat 回合与收敛回合必须保留因果关联、消息序号、状态版本和时间戳。
- 过期收敛回合不得写入当前工作面；它保留 trace 后停止，由最新 Chat 的后置判断重新决定是否触发新的收敛。
- 正常 Chat 不要求每轮留下变化回执；只有实际结构化状态变化才需要可追溯记录。

## 7. 回流与停止

当出现来源冲突、关键上下文缺失、用户尚未确认高影响判断或验证不通过时，收敛回合不得继续压缩为稳定内容。

它应保留当前提案和原因，并让后续正常 Chat 继续引导，而不是进入后台等待确认、用画布操作或自动重试掩盖缺口。
