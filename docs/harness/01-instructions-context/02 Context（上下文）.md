# Context（上下文）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

上下文定义模型当前应该看到什么信息。

在 EvoCanvas 中，这里的“看到”不是泛指任何可读取数据，而是指本轮推理真正应进入模型工作面的内容。

## 2. 上下文不是长聊天历史

EvoCanvas 的上下文核心单位不是消息，而是对象。

当前轮上下文应优先包含：

- 当前用户输入。
- 当前选中对象。
- 当前主题相关来源和证据。
- 未解决的待澄清项。
- 已确认的约束和决策。
- 当前阶段可见的交接包摘要。

默认不应包含：

- 全部历史聊天。
- 全部原始材料全文。
- 与当前主题无关的旧对象。

## 3. 当前主题工作面

EvoCanvas 的上下文更准确地说，是“当前主题工作面”。

这张工作面至少包含六类信息：

1. 当前用户输入：这一轮新增表达、附件、引用卡片和明确指令。
2. 当前主题：当前正在收敛的主题、问题域或交接目标。
3. 当前正式对象：当前相关的卡片、关系、状态和栏目归属。
4. 当前未决项：待澄清、冲突、待决策和阻塞项。
5. 当前稳定事实：已确认约束、已完成决策和已发布交接物摘要。
6. 当前运行提示：本轮变化摘要、待确认动作和必要回执。

## 4. 为什么不是全量上下文

PRD 的目标不是“把所有材料都喂给模型”，而是“降低需求失真”。

因此，上下文如果过满，反而会带来三个问题：

1. 模糊输入会被旧结论压扁，失去对话塑形空间。
2. 未决问题会被长历史稀释，看起来像已经解决。
3. 当前卡片与当前缺口会失去优先级，导致 AI 输出看起来完整但不贴当前工作面。

## 5. 上下文目标

上下文目标不是尽量全，而是足够正确。

更具体地说，它要做到：

1. 让 AI 理解当前用户想推进什么。
2. 让 AI 看见当前哪些内容已经稳定，哪些还不稳定。
3. 让 AI 能把自然语言更新映射到具体卡片、关系和状态。
4. 让 AI 能在必要时追问，而不是因为缺上下文就硬生成。

## 6. 默认不进上下文的内容

以下内容可以保留在系统里，但默认不应直接进入本轮工作面：

1. 与当前主题无关的旧消息。
2. 已被替代的旧版本交接物全文。
3. 无引用关系的长原始材料全文。
4. 个人挂件内容。
5. 不影响当前推进的冷历史对象。
