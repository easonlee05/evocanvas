# Context Assembly（上下文装配）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

上下文装配定义系统如何把当前输入、对象、记忆和来源材料组装成模型可用工作面。

它回答的不是“系统里有哪些数据”，而是“这一轮到底该把哪些数据放进来，按什么顺序放，放到什么程度就够了”。

## 2. 建议槽位

每轮上下文建议保留固定槽位：

- 输入槽位。
- 产品指令槽位。
- 当前主题槽位。
- 当前对象槽位。
- 稳定事实槽位。
- 活跃问题槽位。
- 关键证据槽位。
- 回执与确认槽位。
- 历史补充槽位。

这样做的目的，是防止单一长输入或单一大对象把整个工作面挤满。

## 3. 装配顺序

建议按以下顺序装配：

1. 先放系统级和产品级指令。
2. 再放当前用户输入和本轮明确目标。
3. 再放当前主题和当前选中卡片。
4. 再放当前未决项与当前稳定事实。
5. 再放为当前判断所必需的关键证据和来源片段。
6. 最后才补历史回执、旧快照和冷历史信息。

## 4. 引用卡片时的偏置规则

当用户在右侧 AI 助手里引用某张卡片继续讨论时，上下文装配应显式偏置：

1. 被引用卡片本体优先进入上下文。
2. 该卡片的直接关系对象优先于同主题其他对象。
3. 该卡片关联的待澄清、约束或待决策优先进入。
4. 该卡片直接来源片段优先复水。

这能保证 AI 讨论的是“这张卡片正在承载的工作”，而不是泛泛回到整个项目历史。

## 5. 复水顺序

需要补充信息时，按以下顺序复水：

1. 当前对象直接引用的来源。
2. 当前对象上游证据。
3. 与当前冲突相关的相对证据。
4. 最近相关快照。
5. 必要的历史回合回执。

不建议直接按时间顺序全文回放。

## 6. 何时停止补上下文

上下文装配不是越多越好。满足以下条件后，应优先停止继续补料并进入推理：

1. 已能判断当前输入更像待澄清、约束、待决策还是交接收束。
2. 已能定位主要影响对象。
3. 已具备最小来源线索。
4. 已知道当前是否存在关键冲突或缺口。

如果继续补上下文也不能消除歧义，应优先追问，而不是无限复水。

## 7. 装配失败时的默认动作

当上下文不足、引用失效或冲突过多导致系统无法稳定装配时，默认动作应是：

1. 保留当前输入。
2. 显式提示上下文缺口。
3. 回退到追问或待澄清生成。
4. 避免直接产出看似完整的结论。

这与 PRD 的协作协议一致：不静默合并，不假装已经收稳。
