# Maturity Levels（成熟度层级）

> 当前成熟度层级：`L2 元规则定义层`

## 1. 这一层回答什么问题

本文档定义 EvoCanvas harness 文档的成熟度分层。

它的作用不是做抽象分级装饰，而是约束实现节奏，避免在治理规格尚未收稳时过早编码。

## 2. 四层成熟度

### 2.1 L1 产品原则层

主要回答：

- 产品想解决什么。
- 系统边界在哪里。
- 哪些行为是方向性错误。

### 2.2 L2 对象与流程定义层

主要回答：

- 有哪些核心对象。
- 最小推进链路怎样发生。
- 哪些层之间必须分开。

### 2.3 L3 可指导实现的治理规格层

主要回答：

- 对象最小字段是什么。
- 什么能升级、什么要回退、什么必须拦截。
- 验证器、门禁、状态跃迁规则如何落地。

### 2.4 L4 可直接编码的运行时规格层

主要回答：

- 结构模式（schema）怎么写。
- 状态枚举怎么定。
- 回执、日志、验证结果、治理决定如何持久化。

## 3. 编码门槛

系统级基线是：

- 只有达到 `L3` 的模块，才允许直接作为稳定实现规格。
- 低于 `L3` 的模块，默认优先补 harness 规则，而不是扩写主流程代码。
- 不要求所有模块都达到 `L4` 才能开发，但关键主链至少应先达到 `L3`。

## 4. 对当前文档树的意义

对 `docs/harness/` 而言：

- `00-overview/` 负责建立系统总视角和判断基线。
- 其他层文档应在改写后同步标注自己当前处于 `L1 / L2 / L3 / L4` 哪一层。
- 如果层级变化，应同步更新文档顶部的成熟度说明和编码门槛。

## 5. 使用方式

成熟度分层主要用于三个判断：

1. 这份文档是在讲方向、对象、规则，还是实现。
2. 当前是否已经足够支撑后端和前端落地。
3. 当实现和文档冲突时，是该补规则，还是该修代码。
