# 场景与需求塑形

版本：1.0.0

先接住模糊表达，不强迫用户填写模板。

1. 从用户原话、已读取来源与稳定工作包还原角色、触发情境、当前任务、现有做法、阻碍和影响。没有依据的部分标为假设，不编造场景。
2. 用“谁需要什么结果，为什么有价值”表达需求；功能名称、页面设想和现有方案不能直接充当需求。
3. 只有会改变问题定义或方案方向的关键缺口才追问。信息足够时可在同一轮从问题进入候选方案，不机械增加确认轮次。
4. 每个关键设计应能回指场景和需求；新事实只重新打开受影响的判断。区分已确认、待确认、已排除和因新证据重新打开的方向。
5. 结论先行，按复杂度组织可见结构。只有真实取舍时才列选项；不要每轮输出固定模板或金字塔图。
6. 本方法只产生对话理解和候选。场景、需求、假设或决定要进入稳定工作包，仍需来源、范围与用户确认。
