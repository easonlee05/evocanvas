# Trace Model（追踪模型）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

追踪模型回答：系统内部至少要记录哪些结构化 trace，才能支持回看、诊断和治理回执。

追踪模型面向系统实现，不要求全部直接展示给用户。

它服务的不是抽象链路，而是当前工作台里的具体对象变化。

## 2. 回合追踪

回合追踪记录一次 AI 推进的运行轨迹。

最小字段包括：

- 回合 ID。
- 工作区 ID。
- 当前主题或当前工作面。
- 用户输入摘要。
- 当前阶段。
- 装配的关键上下文对象。
- 本轮结果：已应用、等待确认、已追问、已拒绝、已失败。

如果这一轮只是围绕某张卡片继续讨论，也应能知道它主要影响了哪张卡、哪个栏目或哪个交接主题。

## 3. 状态差异追踪

状态差异追踪记录本轮对工作面造成的变化。

最小字段包括：

- 新增对象。
- 更新对象。
- 状态变化。
- 关系变化。
- Active Todos 投影变化。
- 里程碑提示变化。
- 交接物变化。

状态差异追踪的重点不是“变更量有多大”，而是用户现在工作面上能看到的东西为什么变了。

## 4. 治理追踪

治理追踪记录高影响动作为什么被允许、挂起或拒绝。

最小字段包括：

- 动作类型。
- 受影响对象。
- 风险等级。
- 触发规则。
- 是否需要确认。
- 用户确认结果。
- 最终状态。

对于未通过的高影响动作，也应能保留“为什么没有落盘”。

## 5. 来源链追踪

来源链追踪记录关键对象的依据。

最小字段包括：

- 来源引用。
- 证据卡引用。
- 支撑或冲突关系。
- 确认方式。
- 依赖对象。

当对象进入已生效、已决定、已确认或已过时状态时，来源链追踪尤其关键。

## 6. 异常追踪

异常追踪记录系统为什么没有按预期推进。

最小字段包括：

- 异常类型：输入编译失败、关系解析失败、Todo 投影异常、确认取消、验证失败等。
- 发生阶段。
- 受影响对象。
- 保底动作。
- 用户可见提示。

异常追踪的重点不是报错本身，而是保证系统没有静默丢失输入或误改状态。
