# 交接编排（Handoff Orchestration）

> 当前成熟度层级：`L3 可指导实现的治理规格层`
> 编码门槛：`已达到 L3，可直接指导第一批交接编排与草稿 / 正式边界实现`

本文件展开 L 层中的交接编排基线，集中保存交接物的位置、条目组织原则、草稿 / 正式边界与下游保护口径。

## 这一层回答什么问题

交接编排回答：

- handoff 在 L 层中处于什么位置
- handoff 应从哪些上游对象收束而来
- handoff 的内部结构如何保持已知与未知并存
- 什么时候只能输出草稿，不能输出正式交接物

## handoff 的基本位置

交接物（handoff）不是聊天总结，也不是原话拼装包。

它是面向下一位人或下一轮 AI 的结构化上下文包，先服务于继续推进，再服务于快速读懂。

L 层当前明确以下原则：

- handoff 来源于当前结构化对象，而不是重新自由生成
- handoff 同时包含已知与未知，不得掩盖未解决待澄清项
- handoff 不得绕过确认把草稿（draft）冒充正式版（formal）

## handoff 的主要上游对象

交接物（handoff）的默认编排单位不是原话，也不是聊天回合，而是已经形成的结构化对象。

条目应优先承接：

- 解释对象（interpretation）
- 约束（constraint）
- 待决策候选（decision candidate）
- 已确认决策（confirmed decision）

来源片段（source fragment）默认作为这些条目的追溯依据存在，而不是直接成为 handoff 的主要写作单位。

## handoff 的三层内容结构

handoff 在编排上应显式区分三层内容：

- 已确认内容
- 高置信但未确认内容
- 未决问题 / 待拍板事项

当待拍板事项已经成为当前推进主轴时，handoff 应将其从普通未决问题中抬升为独立槽位。

## 草稿 / 正式边界

关于 handoff 的内部稳定性，当前先保留以下基线：

- 高置信但未确认内容默认不应超过主体内容的三分之一
- 若超过该阈值，handoff 只能保持 draft 状态
- handoff 主体内容按结构化条目数计数
- 每条主体内容只承载一个核心判断

## 单主对象编排原则

handoff 条目默认采用：

`单主对象编排`

也就是：

- 每条条目必须有唯一主对象
- 主对象优先由下游作用决定
- 状态稳定性用于校正主对象选择
- 对象类型只作为最后兜底裁决

非主对象只用于支撑主对象继续推进，默认承担：

- 依据
- 边界
- 风险
- 未决

其中：

- 依据可以细分为当前依据与追溯指针
- 例外默认作为边界的特殊子类处理
- 未决可以附带风险说明，但两者治理上仍应分开

## 拆条规则

handoff 条目的拆分规则应显式区分硬条件与软条件：

- 若出现第二主判断或独立下游动作，必须拆条
- 若只是条目过载、状态过杂、阅读负担过高，则强烈建议拆条

为避免把次要命名问题过度制度化，L 层当前只要求：

- 条目主句能表达主判断
- 条目主句能表达下游方向

除此之外，不要求在 1.0 阶段引入更细的命名算法。

## 条目字段与包层字段的最小治理集

在条目字段层，L 层当前建议采用最小可推进集：

- 主判断
- 状态层级
- draft 标记（可选）
- 下游方向
- 依据摘要 + 追溯指针
- 未决 / 风险提示

在包层字段上，L 层建议保持轻治理外壳：

- 当前目标
- 整体状态
- 适用范围 / 主题边界
- 条目列表
- 整体未决提醒

其中，整体状态建议采用轻量双轴：

- 交接形态：草稿 / 正式（draft / formal）
- 收敛成熟度：进行中 / 可交接 / 已发布
