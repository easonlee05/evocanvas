# Core Object Model（核心对象模型）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

本文档定义 EvoCanvas harness 需要治理的核心对象。

核心原则：对象优先于文本。长对话不是事实层，结构化对象才是系统持续收敛的工作面。

但在 EvoCanvas 里，对象不是为了替代对话，而是为了把 `Vibe Shaping` 过程中逐步稳定下来的内容接入正式对象层，并最终支撑结构化交接物。

## 2. 产品主对象

EvoCanvas 1.0 的产品可见卡片以 PRD 中的卡片体系为准：

1. 证据卡：承接原始材料中与当前主题相关、值得引用的证据片段；原始材料本身独立保存。
2. 问题卡：一个需要解决的实际问题对应一张卡，不预设“主问题 / 子问题”层级。
3. 待澄清卡：承接 Chat 结束后仍未解决、并会影响后续判断的信息缺口。
4. 约束卡：只承接已在 Chat 中确认的术语、字段、状态、权限、流程、计费、边界和数据口径等规则。
5. 待决策 / 方案承接卡：承接需要用户拍板的事项，并保留轻量选项、取舍和推荐，不展开完整方案。
6. 交接物承接卡：在交接内容已经可阅读、可评审时，显影当前结构化包版本与交接模块。

前五类卡片对应正式业务对象，参与类型化状态、关系、确认和 Active Todos 投影。交接物承接卡是同一结构化包版本的可视化入口，其正文和有效状态来自包版本与状态账本，不创建第六份可独立修改的业务对象。

不同卡片类型表达不同事实，不通过改写对象类型假装它们是同一件事：

- 待澄清卡记录“当时缺什么”；被回答后保留原身份，并进入已澄清或已关闭状态。
- 确认结果若形成稳定边界，另建约束卡；若完成真实取舍，更新或另建待决策 / 方案承接卡。
- 同一次确认同时包含取舍过程和后续稳定边界时，可以同时形成已决定事项与已生效约束，并通过 `产出为` 等关系连接。
- 已澄清或已关闭的待澄清卡退出主画布默认当前视图；已决定事项继续作为稳定决策结构显影，直到被重新打开、替代或归档。

## 3. 后端辅助对象

为了让主对象可追溯，后端可以保留更细的辅助对象：

- 来源片段（source fragment）：从原始输入中摘出的可引用片段。
- 解释对象（interpretation）：AI 对来源形成的可挑战中间理解。
- 候选提案（proposal）：本轮准备写入、更新或申请信息地位升级的结构化变更。

这些辅助对象不应替代 PRD 卡片成为产品主对象。它们服务于来源链、验证、治理和可观测性。

## 4. 事实可用性层级

### 4.1 原始输入

保存会议纪要、聊天摘录、截图说明、反馈、数据说明等原始材料。

特点：可引用、可追溯，但不直接等于系统结论。

### 4.2 结构化候选

保存 AI 从输入中抽取和提出的证据片段、问题、Chat 后残留的待澄清、待决策候选或达到可评审条件的交接草稿。约束提议在 Chat 中完成确认前，不进入结构化候选卡片层。

特点：可以显影为草稿或候选，但不自动等于已成立依据。

### 4.3 待确认对象

对象已经具备足够信息，但仍需要用户明确确认。

特点：由后续正常 Chat 继续确认产品判断与范围，但不能被下游当作已生效内容。

### 4.4 生效中对象

保存已满足生效条件的约束、已决定事项、已澄清缺口和已确认交接物。

特点：可成为后续推理、交接或下游 AI 的依据，但必须可追溯。

### 4.5 过时或归档对象

对象曾经可用，但由于新输入、新约束或新决策已经不适合作为当前依据。

特点：不直接删除，应保留历史和替代关系。

## 5. 对象治理底线

- 证据卡是事实输入的结构化投影，不代表正式结论。
- 问题卡不是待决策结果，也不是交接结论。
- 待澄清卡是 Active Todos 的主要来源，但 Todo 不是独立事实源。
- 未经 Chat 确认的约束提议不得写入或显影为约束卡。
- 一张约束卡只承载一条可以独立确认、修改、替代或废止的规则；共同出现不等于必须合并成一张卡。
- 产品内部规则可以由有权用户的明确确认成立；法规、平台政策、技术极限和数据结论等外部事实还必须有可核对来源。
- 待判断事项不得被写成已决定结果。
- 未确认交接物不得被标记为可直接外发或交给下游 AI 执行。

## 6. 对象层与界面层的关系

为了避免把视觉表现误当成事实层，系统至少应区分五层：

- 对话流：用户与 AI 的原始交互过程。
- 结构化对象：系统治理的工作对象本体。
- 结构化包版本：保存当前主题下对象、关系和交接引用的不可变工作快照。
- 卡片：业务对象或结构化包版本在画布中的可视化回显与操作入口。
- 交接物：达到治理条件的结构化包版本及其交接视图。

因此：

- 卡片不是原始事实来源。
- 交接物不是原始事实来源。
- 原始依据应来自输入内容、来源引用和可追溯判断链。

## 7. 卡片、系统挂件与个人挂件

按 PRD 边界，工作台可见对象分为三层：

- 卡片：业务对象或包版本的正式产品投影，参与对应关系、状态展示和结构化交接。
- 系统挂件：由系统投影出的辅助视图，例如 Active Todos 和轻量里程碑条。
- 个人挂件预留：服务个人思考和操作便利的工作台工具。

对 harness 而言，这三层的治理要求不同：

- 卡片进入正式对象链路。
- 系统挂件可以帮助看清状态，但不能成为独立事实源。
- 个人挂件默认不进入结构化交接物，也不应被直接视为已确认事实。
