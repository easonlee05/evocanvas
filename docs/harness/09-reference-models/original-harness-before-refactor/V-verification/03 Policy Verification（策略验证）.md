# 策略验证（Policy Verification）

## 1. 策略验证回答什么

策略验证回答的是：

`这次收敛有没有违反 EvoCanvas 1.0 的推进原则`

它不重新做来源判定，也不替代结构检查，而是专门防止“结果看起来完整，但收敛路径已经失真”。

## 2. 策略验证的默认检查范围

策略验证至少检查以下三类问题：

- 是否跳过了应显性化的不确定性
- 是否把仍待选择的问题偷换成已成立边界
- 是否把交接物当成自由总结，而不是受约束的结构化交接层

因此，策略验证本质上是在守产品方法论，而不是守字段格式。

## 3. 待澄清相关的策略检查

以下情况默认应判为策略风险：

- 在明显缺口存在时跳过待澄清项（clarification）
- 把低价值未知误升级成关键待澄清
- 把应继续显性化的问题过早压成稳定结论

待澄清项的策略验证重点不在“问得多不多”，而在：

- 问题是否真的指向关键缺口
- 问题是否会影响后续约束或待决策
- 不回答是否真的会污染推进

## 4. 约束、待决策与交接相关的策略检查

以下情况默认应判为错误收敛：

- 在明显缺口存在时形成稳定约束
- 把冲突压成模糊中间说法
- 在证据不足时形成待决策候选
- 在未解决待澄清项过多时直接生成看似完整的结构化交接物
- 把偏好误写成约束
- 把解释对象直接越级写成已确认决策

因此，策略验证的核心是防止“提前完成”。

## 5. 高影响动作的策略检查

对高影响动作，策略验证至少还要检查：

- 当前结果是否已经经过应有的显性化与分层
- 当前高置信未确认内容是否被错误伪装成已确认内容
- 当前动作是否绕过了应有的确认或治理位

如果这些检查未通过，默认只允许给出更保守的推进建议，不允许继续硬推进。
