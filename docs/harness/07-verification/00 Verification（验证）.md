# Verification（验证）

> 当前成熟度层级：`L3 可指导实现的治理规格层`
> 编码门槛：`可作为 1.0 结构验证、来源验证、策略验证与验证结果表达的实现输入`

## 1. 这一层回答什么问题

验证（verification）回答：这一次写入、更新、迁移、确认或交接收束，是否已经满足“可以继续推进”的最低可信条件。

它不回答“这个能力长期是否值得保留”，那属于评估（evaluation）。

在 EvoCanvas 1.0 中，验证服务的主链是：

```md
输入编译 -> 待澄清问题 -> 约束 / 待决策 -> 结构化交接物
```

它主要拦住三类失真：

- 结构不成立的对象被显影到画布。
- 没有足够依据的判断被当成稳定内容继续使用。
- 收敛路径已经跳步，但表面上看起来“已经完成”。

## 2. 验证和治理、编排的边界

验证判断“现在够不够可信”，治理判断“能不能生效”，编排判断“下一步往哪走”。

例如：

- 验证可以说：这张约束卡缺少确认方式，不能进入已生效判断。
- 治理可以说：这次是高影响动作，必须先经过确认请求。
- 编排可以说：本轮应该补来源、转成待澄清，还是挂起等待确认。

所以验证既不是放行层，也不是阶段推进层，而是 `可信度检查层`。

## 3. 这一层验证什么

[Structure Verification（结构验证）](./01%20Structure%20Verification%EF%BC%88%E7%BB%93%E6%9E%84%E9%AA%8C%E8%AF%81%EF%BC%89.md) 检查对象、关系、状态与动作载荷在形式上是否成立。

[Source Verification（来源验证）](./02%20Source%20Verification%EF%BC%88%E6%9D%A5%E6%BA%90%E9%AA%8C%E8%AF%81%EF%BC%89.md) 检查当前判断是否有足够依据、是否可回溯、是否已显式处理冲突。

[Policy Verification（策略验证）](./03%20Policy%20Verification%EF%BC%88%E7%AD%96%E7%95%A5%E9%AA%8C%E8%AF%81%EF%BC%89.md) 检查这次收敛是否遵守 EvoCanvas 1.0 的产品方法：先暴露不确定性，再沉淀约束，再形成待决策，最后生成交接物。

## 4. 验证挂载点

验证不需要每轮对所有对象全量执行，但以下场景必须挂载：

### 4.1 对象准备显影到正式工作面

包括：

- 输入编译结果准备进入卡片层。
- 待澄清、约束、待决策、交接物承接内容准备创建。
- 卡片关系准备写入并影响画布解释。

### 4.2 对象准备升级状态

包括进入：

- 待确认
- 已生效
- 已决定
- 已确认
- 已过时
- 已关闭 / 已阻塞 / 已澄清

### 4.3 高影响动作准备执行

包括：

- 跨栏目或跨阶段迁移后准备接受轻确认。
- 关闭关键待澄清。
- 将约束写成已生效。
- 将待判断内容写成已决定。
- 生成、刷新或确认交接物承接卡。

### 4.4 工作面投影准备变化

包括：

- Active Todos 的新增、关闭与阻塞判断。
- 里程碑进度变化。
- 交接物是否进入可继续推进、待确认或已过时状态。
- 变化摘要是否准确表达了本轮真正发生的结构变化。

## 5. 验证结果如何表达

验证结果至少要能表达：

- 这次验的是哪个对象、关系或动作。
- 跑了哪类验证。
- 结果是通过、失败、通过但告警，还是未完成验证。
- 关键依据是什么，或者缺了什么。
- 建议下一步是什么。

这里的“建议下一步”通常包括：

- 继续推进
- 补字段
- 补来源
- 显性化冲突
- 回到待澄清
- 转成待决策
- 等待确认
- 降级为草稿或提案

## 6. 默认分流方向

验证失败后，不应静默吞掉，也不应继续硬写入。

默认分流方向如下：

- 结构不成立：补字段、修正类型，或降级为草稿。
- 来源不足：补来源、标记来源缺失，或回到待澄清。
- 冲突未处理：显性化冲突，并视影响范围转入待澄清或待决策。
- 策略跳步：回到更保守的收敛位，而不是假装已经完成。
- 高影响动作缺确认：保持待确认，不允许直接落成正式结果。

## 7. 设计禁令

- 不允许把“写得像成品”当作验证通过。
- 不允许让生成动作自己无条件判定自己正确。
- 不允许把用户确认当成所有验证的替代物。
- 不允许让冲突、缺口或未决在交接物里被伪装成已稳定结论。
- 不允许让验证结果只停留在内部，而用户可见工作面却无法解释为什么变了或为什么没变。
