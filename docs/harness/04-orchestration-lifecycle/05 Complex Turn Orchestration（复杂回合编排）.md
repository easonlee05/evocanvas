# Complex Turn Orchestration（复杂回合编排）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

复杂回合编排回答：

- 什么情况下单轮简单编排不够。
- 系统如何处理冲突、多候选方向和过早收敛风险。
- 一轮复杂处理如何避免无限循环。

## 2. 启用条件

遇到以下情况，建议启用复杂回合编排：

- 输入信息明显冲突。
- 用户表达同时包含多个候选方向。
- 当前主题边界模糊，无法直接形成稳定对象。
- 准备生成交接物，但待澄清项仍较多。
- 系统判断当前存在过早收敛风险。

复杂回合编排不是新主流程，只是当前回合里的临时处理方式。

它解决的是“单轮简单编排已经不足以安全收敛”，而不是让系统再长出一条平行主链。

## 3. 默认三步

复杂回合默认拆成三步：

1. 打开问题：列出冲突、缺口、候选解释和需要补证据的点。
2. 收束结构：把可保留内容映射为待澄清、约束候选、待决策候选或交接草稿。
3. 裁决去向：判断是继续追问、挂起确认、回流，还是进入下一阶段。

这三步对应的是语义角色，不要求 1.0 一开始就做成显式多 agent 架构。

## 4. 权限边界

### 4.1 打开问题时可以做

- 暴露冲突。
- 提出候选解释。
- 提出需要补充的来源。
- 生成待澄清。

不可以：

- 关闭关键待澄清。
- 标记约束已生效。
- 发布交接物。

### 4.2 收束结构时可以做

- 合并重复候选。
- 生成结构化提案。
- 形成最小可推进结构。

不可以：

- 删除关键冲突。
- 把提案升为稳定事实。
- 用摘要掩盖来源断裂。

### 4.3 裁决去向时可以做

- 判断是否继续追问。
- 判断是否需要确认。
- 判断是否回流。
- 判断是否进入下一阶段。

不可以：

- 增写新事实。
- 代替用户确认。
- 绕过高影响动作门禁。

## 5. 输出要求

复杂回合即使没有形成稳定结果，也必须留下可继续推进的最小输出，例如：

- 新增待澄清。
- 新增冲突标记。
- 生成待决策建议。
- 明确说明当前为什么只能停留或回流。

不允许复杂回合只在内部“想了一圈”，对用户没有任何可见结果。

## 6. 循环约束

复杂回合不应无限循环。

建议约束为：

- 单回合最多一次主打开问题。
- 单回合最多一次主收束结构。
- 单回合最多一次去向裁决。

如果仍无法形成可继续推进的最小结果，系统应回到主阶段骨架中的停留、追问、回流或门禁处理，而不是在复杂回合中自转。
