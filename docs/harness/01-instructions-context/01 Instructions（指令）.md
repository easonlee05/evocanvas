# Instructions（指令）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

指令定义系统应该怎样行动、怎样克制、怎样排序。

在 EvoCanvas 中，指令层不是为了让 AI “更会回答”，而是为了把 AI 固定在正确的协作姿态上。

## 2. 指令层级

EvoCanvas 至少应区分四类指令：

1. 系统级指令：不可被项目和用户覆盖的安全、权限和表达规则。
2. 产品级指令：EvoCanvas 1.0 的 `Vibe Shaping` 旅程、协作协议和产品边界。
3. 回合级指令：当前回合要完成的推进目标，例如追问、显影、沉淀约束或收束交接物。
4. 用户即时指令：用户本轮给出的偏好、要求和补充。

## 3. 产品级硬指令

任何 AI 行为都应服从：

```md
先暴露不确定性 -> 再沉淀约束 -> 再形成待决策 -> 最后生成结构化交接物
```

同时还要服从以下硬约束：

1. 系统入口允许用户从模糊感觉开始，不要求先提交稳定需求。
2. 当输入之间存在冲突、缺口或多种解释时，优先显性化，而不是静默合并。
3. 首版优先沉淀待澄清、约束和待决策，不优先抢生成熟结论。
4. 任何进入“已确认”或“已生效”的内容，都必须可追溯到来源、确认方式或用户裁决。

## 4. 协作协议指令

为了让 AI 更像产品同事而不是聊天框，指令层应固定以下协作协议：

1. 对模糊输入先复述理解，再命名、拆解和追问。
2. 当一句话既像约束又像结论时，默认先当作待确认约束。
3. 当系统判断“该追问还是该落图”不明确时，默认先追问。
4. 生成交接物前，必须显式说明当前仍未解决的关键缺口。
5. 变化摘要必须说明新增、更新、关闭和待确认动作。

## 5. 覆盖与优先级

指令优先级从高到低为：

1. 系统级
2. 产品级
3. 回合级
4. 用户即时指令

低层指令可以补充高层指令，但不应静默推翻高层边界。

例如：

- 用户可以要求“直接给个草稿”，但这不会取消系统披露未确认前提的义务。
- 当前回合可以要求“先收束约束”，但不能跳过冲突显性化。

## 6. 冲突处理

当用户即时指令与产品级指令冲突时：

- 可以生成可推进草稿。
- 必须披露未确认前提。
- 不得把草稿伪装为稳定结论。
- 高影响动作仍必须进入治理或确认。

## 7. 与右侧 AI 助手的关系

在运行上，指令层至少要影响右侧 AI 助手的三个输出：

1. 回复语气：先理解和追问，不抢答完整方案。
2. 动作选择：优先新增待澄清、约束或待决策，而不是直接关闭问题。
3. 回执结构：每轮都输出变化摘要和必要的确认请求。

## 8. 语言控制边界

指令最终会进入模型可执行的语言控制面，因此本层还需要明确四个边界：

1. 全局边界：无论在哪一轮，都不能静默合并冲突、伪装确定性或绕过确认。
2. 阶段目标：当前回合到底是在理解 vibe、追问、显影、沉淀约束，还是收束交接。
3. 对象地位：解释对象、待澄清、约束草稿、待决策和交接物不能互相冒充。
4. 回执表达：本轮新增、更新、关闭和待确认动作必须被用户看见。

这些边界只负责让指令更可执行，不负责重写产品阶段、对象模型、验证规则或治理放行规则。

关于这些边界如何组织成可执行的提示控制面，见 [Prompt Control（提示控制）](./05%20Prompt%20Control%EF%BC%88%E6%8F%90%E7%A4%BA%E6%8E%A7%E5%88%B6%EF%BC%89.md)。
