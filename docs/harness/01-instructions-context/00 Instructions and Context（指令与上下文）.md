# Instructions and Context（指令与上下文）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 分组目的

本组同时放置“指令”和“上下文”，但二者不是同一概念。

- 指令（instructions）回答：系统应该如何行动。
- 上下文（context）回答：系统当前基于什么信息行动。

在 EvoCanvas 1.0 中，这一组文档主要服务两件事：

1. 把 AI 固定成符合产品协议的“产品同事式协作体”。
2. 把右侧 AI 助手每一轮真正看到的工作面控制在正确范围内。

## 2. 边界声明

指令不是上下文的一部分，上下文也不是记忆本体。

- 指令是规范层。
- 上下文是当前工作面。
- 记忆是可复用历史。

本组只讨论前两者；记忆和状态在 `02-memory-state/` 中展开。

同时要再区分一层：

- 指令决定“该怎么做”。
- 上下文决定“基于什么做”。
- 记忆决定“过去哪些内容可在需要时被复用”。

## 3. 设计目标

EvoCanvas 的指令与上下文系统要保证：

- `Vibe Shaping` 的产品协议稳定进入每轮推理。
- 当前用户输入、当前主题、当前卡片和当前缺口被优先看见。
- 待澄清、约束和待决策优先级不会被长对话淹没。
- 原始材料按需复水，而不是全文塞入模型。
- 右侧 AI 助手输出的变化摘要、确认请求和卡片跳转都能回到统一工作面。

## 4. 这一组的核心结论

EvoCanvas 的 AI 不是基于“完整聊天历史”来工作的，而是基于“当前主题工作面”来工作的。

这个工作面至少同时受两层约束：

1. 指令层约束：先暴露不确定性，再沉淀约束，再形成待决策，最后生成结构化交接物。
2. 上下文层约束：优先看当前输入、当前卡片、当前未决问题、当前已确认约束，而不是无差别看所有历史消息。
