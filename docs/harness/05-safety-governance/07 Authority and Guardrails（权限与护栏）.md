# Authority and Guardrails（权限与护栏）

> 当前成熟度层级：`L3 可指导实现的治理规格层`

## 1. 这一层回答什么问题

权限与护栏回答：AI、系统和用户分别能做什么，哪些动作必须经过确认，确认结果如何影响画布状态。

EvoCanvas 1.0 默认是单人工作台，不引入复杂多人权限系统。这里的权限主要是 AI 动作权限和用户确认权。

## 2. 权力关系

1. 用户拥有当前画布内操作和裁决权。
2. AI 助手拥有理解、整理、建议和低风险更新权。
3. 系统拥有验证、风险分级、门禁和状态账本记录责任。
4. 高影响信息地位升级必须经过用户在 Chat 中的确认后才可生效。

一句话：AI 可以推动，但不能越过用户确认改变事实边界。

## 3. AI 可自动执行的动作

AI 在规则允许时可以自动执行：

- 新增相关证据片段卡。
- 新增问题卡。
- 新增 Chat 后仍影响推进的待澄清卡。
- 新增或更新待决策 / 方案承接候选。
- 创建或刷新达到可评审条件的交接草稿。
- 建立弱关系。
- 标记冲突。

这些动作仍需留痕，但不要求每次弹出确认。

## 4. AI 不可直接自动生效的动作

AI 不可直接自动生效：

- 新增、实质修改或替代约束卡。
- 将待决策 / 方案承接卡改为已决定。
- 将待澄清卡改为已澄清或关闭关键待澄清问题。
- 将交接版本改为已确认或可供下游依赖。
- 调整其他会改变事实边界的语义状态。

这些信息地位升级只有在 Chat 中已经形成清晰、带范围的用户确认后，才能由收敛回合验证并落盘。若 Chat 尚未聊清楚，系统可以保留候选或未决，由后续正常 Chat 继续说明建议、依据、影响和未决。画布不承担高频确认流程。

## 5. Chat 确认依据的最小内容

确认不是礼貌弹窗，也不是画布上的待办卡，而是 Chat 中可追溯的事实依据。如果当前讨论已经包含清晰提议和用户确认，不得要求用户重复确认。

一条可用于高影响状态升级的确认链至少能回答：

1. 用户确认的具体判断或动作是什么。
2. 适用对象和范围是什么。
3. 确认基于哪些上下文或建议。
4. 哪些相关问题仍未一起解决。
5. 对应的 Assistant 提议与 User 确认消息在哪里。

Chat 完成后，后置判断器可以把明确确认视为强触发信号。收敛回合验证确认范围后更新结构化包和状态账本，再同步相关 Todo、里程碑或交接物状态并投影画布。

用户明确否定或撤回时，不得把原建议写成已确认内容；原始消息本身保留为追溯依据。若否定形成了新的产品判断，再由正常后置判断决定是否收敛。

## 6. 护栏禁令

- 不允许把提案当作已生效对象。
- 不允许在高影响信息地位升级上默认自动通过。
- 不允许冲突只存在于 AI 内部推理中。
- 不允许未确认对象伪装成已确认对象。
- 不允许结构化交接物掩盖关键未知项。
- 不允许让画布卡片、Toast 或固定回执替代 Chat 中的确认。
- 不允许下游 AI 使用未确认内容时不带风险说明。

## 7. 后续版本边界

多人权限、角色审批、团队协作流和复杂评审流不属于 1.0 必须范围。

1.0 只需要先证明：单人工作台中，AI 可以受控推进画布，但不能绕过确认规则改变事实边界。
