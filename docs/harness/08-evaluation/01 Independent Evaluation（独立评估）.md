# Independent Evaluation（独立评估）

> 方法成熟度：`L3 可指导实现的治理规格层`
> 目标实现归属：`离线评估运行器 + 独立人工评审`
> 当前实现状态：`合同已定，评估集待建设`
> 实现说明：独立评估与线上 Pi 运行分离；可复用 Pi Runtime 执行候选，但不让被评系统自评并直接放行。

## 1. 控制目标

减少同一 Prompt、同一 Agent 或同一设计者对自身结果的确认偏差，使发布判断基于可重复输入、隐藏标签和独立评分。

## 2. 独立性要求

- 固定挑战集的期望答案和关键不变量不向被评系统暴露。
- 候选与基线使用相同输入、权限、工具可用性和外部来源快照。
- 人工评审默认不知道结果来自候选还是基线。
- 评审人员不能只看最终交接，必须能在需要时核对来源和确认链。
- 自动裁判只评估结构化、可复现规则；开放语义评分需要明确 rubric 或人工复核。

## 3. 样本分层

至少覆盖：模糊感觉、多源冲突、信息缺失、用户改变决定、直接编辑、未验证外部前提、长会话压缩、权限拒绝、提交超时、投影落后和过时交接。

每个关键分层必须达到 Evaluation Policy 规定的最小样本数；低于最小数时只报告观察，不作发布结论。

## 4. 评分与复核

- 确定性不变量由机器判定。
- 交接忠实度、问题命名质量和下游理解由至少两名独立评审或一个人工评审加一个已校准裁判评估。
- 评分分歧超过 Policy 阈值时进入第三方复核。
- 裁判模型版本、Prompt 和校准集必须记录，不得把裁判分数当无条件事实。

## 5. 数据保护

真实回放先脱敏并取得允许的使用范围。评估制品不得把生产密钥、受限来源正文或用户身份复制到无权限环境。删除请求必须传播到评估样本索引和派生数据。

## 6. 失败与恢复

| 原因码 | 行为 |
| --- | --- |
| `eval.dataset_leakage` | 隔离污染样本并重建测试集 |
| `eval.sample_insufficient` | 结果 inconclusive |
| `eval.judge_disagreement` | 进入复核，不自动平均放行 |
| `eval.environment_mismatch` | 作废候选/基线比较并重新运行 |
| `eval.trace_incomplete` | 样本不能用于可追溯结论 |
| `eval.privacy_violation` | 停止评估、隔离数据并审计 |

## 7. 验收场景

1. 被评 Pi 无法读取隐藏期望标签。
2. 候选与基线工具权限不同的运行不会被直接比较。
3. 两名评审严重分歧时触发复核。
4. 一个高分但 Trace 缺失的样本不能证明系统通过。
5. 真实数据删除请求能定位并处理对应评估副本。
