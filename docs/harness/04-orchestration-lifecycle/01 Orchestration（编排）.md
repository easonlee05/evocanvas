# Orchestration（编排）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

编排回答：当前这一轮应该如何调度。

它关注：

- 当前输入更像感觉、事实材料、问题表达、方案想法、约束线索还是待决策线索。
- 本轮应该继续追问、生成待澄清、沉淀约束、形成待决策，还是生成交接草稿。
- 什么时候调用工具。
- 什么时候进入验证。
- 什么时候挂起等待用户确认。
- 本轮如何输出变化摘要。

编排处理的不是抽象“回答”，而是一次次对当前工作面的 `结构化变更集`。

## 2. 两条主入口

EvoCanvas 1.0 当前有两条主要入口：

1. 输入编译台：处理导入材料、长文本和批量输入。
2. 右侧 AI 助手：处理持续对话、局部更新、追问、确认和变化摘要。

两条入口共用同一套收敛顺序，但装配上下文和输出粒度不同。

## 3. 默认编排顺序

EvoCanvas 1.0 的默认编排顺序是：

```md
接收输入
-> 识别意图
-> 装配当前主题工作面
-> 判断当前阶段目标
-> 生成结构化提案
-> 必要时调用工具
-> 验证来源、结构和策略
-> 风险分级
-> 应用 / 挂起确认 / 追问 / 拒绝
-> 输出变化摘要
```

这条顺序同时适用于输入编译台和右侧 AI 助手，只是入口不同。

## 4. 输入编译台的编排

输入编译台主要处理成批材料或较长输入。

默认调度顺序是：

1. 接收原始输入并保留来源。
2. 识别输入类型。
3. 分段或摘要，不丢失原文指针。
4. 提取事实、问题、冲突和缺口。
5. 生成结构化候选对象。
6. 判断是否足够显影到画布。
7. 输出理解摘要和待澄清问题。

如果输入过于模糊，系统应先追问，不直接显影为高影响结论。

## 5. 右侧 AI 助手的编排

右侧 AI 助手处理持续对话和局部画布更新。

默认调度顺序是：

1. 识别用户当前意图。
2. 定位相关卡片、栏目或当前主题。
3. 判断当前动作类型。
4. 生成更新建议。
5. 根据风险等级决定自动应用、挂起确认或只追问。
6. 输出本轮变化摘要。

其中动作类型至少包括：

- 继续追问。
- 显性化冲突。
- 新增待澄清。
- 补充约束说明。
- 生成待决策。
- 生成交接物草稿。

这一入口还必须处理两类用户直接操作后的语义同步：

- 轻量原地编辑：标题、摘要被修改后，当前卡片语义需要重新进入本轮收敛判断。
- 合法跨栏目迁移：例如待澄清卡迁到约束或待决策承接位时，必须触发轻确认或高影响确认，而不是把拖拽当成纯视觉移动。

## 6. 编排结果类型

每轮编排结束后，系统只允许进入四类结果之一：

1. 自动应用：低风险结构整理可以直接写入。
2. 挂起确认：高影响动作进入确认请求。
3. 只追问：信息不足、指代不清或冲突未解时，不写入主对象层。
4. 拒绝或失败：输入无法理解、结构不成立或异常未恢复。

## 7. 低风险与高影响动作

低风险动作可以在规则允许时自动应用：

- 新增证据卡。
- 新增问题卡。
- 新增待澄清卡。
- 更新约束说明补充。
- 建立弱关系。
- 标记冲突。

高影响动作必须挂起确认：

- 新建待决策 / 方案承接内容。
- 将约束卡改为已生效。
- 关闭关键待澄清问题。
- 生成或刷新交接物承接结果。
- 调整高影响推进状态。

## 8. 编排不负责什么

编排不负责：

- 宣布事实已经生效。
- 替代验证判断结构是否过关。
- 替代治理决定高影响动作能否放行。
- 把工具结果直接写成稳定结论。

编排只负责把当前回合带到正确的下一步。
