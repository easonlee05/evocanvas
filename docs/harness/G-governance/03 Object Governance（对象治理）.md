# 对象治理（Object Governance）

> 当前成熟度层级：`L3 可指导实现的治理规格层`
> 编码门槛：`已达到 L3，可直接指导第一批实现、接口设计与最小验证`

本文件用于展开治理层总览中的“对象生效与回退”，集中保存核心结构化对象的最小治理基线与升级 / 回退规则。

## 对象生效规则

### 证据（evidence）

只要有来源即可成立，但不自动推出结论。

### 来源片段（source fragment）

来源片段（source fragment）是底层依据对象，采用标准化摘录型。

允许：

- 去除口语赘余
- 补足明显省略的主语或指代
- 拆分过长句子

不允许：

- 改变原意
- 把解释偷偷写进来源
- 用重写语义替代原始边界

#### 来源片段的最小治理基线

为便于实现与后续引用，来源片段（source fragment）当前可先采用以下最小治理基线：

- 最小字段集包括：
  - 片段内容
  - 来源位置
  - 来源类型
  - 标准化说明
  - 是否存在边界压缩风险

其中：

- 标准化说明默认采用“标准化类型 + 简短说明”：
  - 不只记录做了哪类标准化处理
  - 也说明大致是如何处理的

- 边界压缩风险默认采用“布尔值 + 关注标记”：
  - 默认只记“有 / 没有”
  - 只有当这段来源片段（source fragment）已经可能影响后续解释对象（interpretation）或约束（constraint）准确性时，才额外挂重点关注标记

- 来源位置默认采用“来源对象内的位置”：
  - 不只知道它来自哪个来源对象
  - 还要能定位到对象内部的大致位置，例如消息段落、文档段落、截图区域或时间点

- 来源类型默认采用“媒介 + 语义来源”：
  - 不只区分它来自什么媒介
  - 还区分它在产品工作流中的来源语义，例如消息摘录、会议纪要、文档片段、截图说明、用户反馈

### 解释对象（interpretation）

解释对象（interpretation）是 agent 对一个或多个来源片段形成的可挑战中间理解层。

治理要求包括：

- 可以由多个相关来源片段共同生成
- 一个对象只允许承载一个核心判断
- 可以带轻量置信度
- 低置信解释可以存在，但不得越级冒充正式结论

当低置信解释会影响后续约束、决策或交接包质量时，应升级生成澄清（clarification）。

#### 解释对象的最小治理基线

为便于实现与后续引用，解释对象（interpretation）当前可先采用以下最小治理基线：

- 最小字段集包括：
  - 核心判断
  - 置信状态
  - 关联来源片段（source fragment）
  - 判断类型
  - 是否存在待澄清风险

其中：

- 一个解释对象只承载一个核心判断
- 判断类型默认只保留三类：
  - 事实判断
  - 意图判断
  - 边界判断
- 关系判断默认不作为基础类型；只有当它已经稳定成为独立治理需要时，才单独升出来

置信状态默认采用三值但弱语义：

- 低：明显需要谨慎使用
- 中：可继续参与推理，但不应直接推动高风险收敛
- 高：在当前证据下相对稳定，但仍不等于正式事实

待澄清风险默认采用“布尔值 + 关键升级标记”：

- 默认只记“有 / 没有”
- 只有当它已经达到应升级为关键待澄清项（critical clarification）的门槛时，才额外挂关键标记

#### 高置信与较高稳定度的区分基线

为便于实现与后续引用，解释对象（interpretation）中的“高置信”与“较高稳定度”可先采用以下区分：

- 高置信用于回答：在当前证据下，这个解释对象（interpretation）看起来有多稳
- 较高稳定度用于回答：它现在是否已经稳到可以推动更高一级对象升级

也就是说：

- 高置信是对象内部状态
- 较高稳定度是升级判定状态
- 高置信不自动等于较高稳定度

默认情况下：

- 较高稳定度要求高置信作为前提
- 只有在极少数例外场景下，才允许不完全满足这个前提
- 这些例外至少要同时满足：对象类型更接近边界确认，且下游影响非常局部

对“较高稳定度”的进一步判断，默认还应遵守以下规则：

- 如果底层关键来源片段（source fragment）仍带边界压缩风险，则高置信可以保留，但默认不直接视为较高稳定度；只有当该风险已被补充来源或回看动作有效消解时，才可能恢复
- 如果仍依赖单一来源片段（source fragment），则默认采用条件单源高稳：
  - 单一来源不自动排除较高稳定度
  - 但必须同时满足：来源足够明确、稳定、直接，没有明显边界压缩风险，且当前升级不会形成高影响对象的误固化
- 如果只是多条彼此相近的来源片段（source fragment）重复支撑，则默认采用条件增强：
  - 重复支撑可以增强高置信
  - 但对较高稳定度的提升默认有限
  - 只有当这些来源片段确实从不同切面减少了解释跳跃或边界压缩风险时，才明显增强较高稳定度

### 待澄清项（clarification）

只要确实存在未知、冲突或缺口即可成立。

待澄清项（clarification）不是所有不确定性的统称，而是会影响后续判断推进的信息缺口。它既可以针对事实缺口，也可以针对意图缺口。

其最小结构至少应包含：

- 要问什么
- 为什么要问
- 如果不回答，会阻塞或污染什么

关键待澄清项（critical clarification）的判定采用两步法：

- 先看它是否阻断约束、决策或交接物形成
- 再看它是否虽然暂不阻断推进，但会污染多个核心对象、全局口径或后续判断

只要满足其中之一，就应提升为关键待澄清项。

当待澄清项（clarification）被回答后，默认不直接越级进入正式事实层，而应先回流更新解释对象（interpretation）。

只有在以下条件同时满足时，才允许有限直升：

- 回答内容基本单义
- 当前冲突较低
- 风险较低
- 不会改变多个下游依据

这里所说的“单义”，默认采用更严格口径：

- 语义上基本只有一种合理解释
- 指向唯一主下游对象
- 不会顺带重写已有边界，也不会引出新的核心歧义

有限直升的上限默认是：

- 约束（constraint）
- 待决策候选（decision candidate）

不允许因为回答了一个待澄清项，就直接越级形成已确认决策（confirmed decision）。

这里所说的“不会改变多个下游依据”，默认采用“依据扇出”口径：

- 重点不是表面上改动了几个对象
- 而是这条回答会不会成为多个核心判断的共同新前提

因此：

- 即使表面上只更新一个对象，只要这个对象会反过来重写多条核心判断的依据链，也应视为“改变多个下游依据”
- 这类情况不应走有限直升，而应先回流解释对象（interpretation）层，再重新判断后续升级路径

这里所说的“低风险回答”，默认不按内容类型粗略判定，而按是否改变事实边界与下游依据来判定。

也就是说：

- 内容类型只能作为辅助参考
- 真正关键的是，这条回答是否会改变事实边界
- 或是否会重写下游判断所依赖的依据链

只要满足其一，就不应被视为低风险回答。

如果某个回答本身不改变事实边界，但会明显改变推荐倾向，则默认采用条件看待：

- 若只是局部排序微调，且不改变正式边界，仍可视为低风险
- 但只要它会实质改变待决策候选（decision candidate）的推荐方向，就不再视为低风险

如果某个回答同时具备“消解旧冲突”与“引入新边界”两种效果，则默认采用分段处理：

- “消解旧冲突”可以计为收敛收益
- “引入新边界”必须单独评估是否改写事实边界与下游依据

系统不应只看净效果来粗略判定风险，也不应因为存在收敛收益，就自动放松对新边界的治理要求。

#### 待澄清项回答后的治理路径摘要

为便于实现与后续引用，待澄清项（clarification）被回答后的治理路径可先概括为以下基线：

- 默认先回流解释对象（interpretation）层，而不是直接越级进入正式事实层
- 只有在回答内容单义（unambiguous）、低冲突（low conflict）、低风险（low risk）、且不会改变多个下游依据时，才允许有限直升（limited promotion）
- 有限直升的上限默认是约束（constraint）或待决策（decision candidate），不直接形成已确认决策（confirmed decision）

其中：

- “单义（unambiguous）”采用更严格口径：语义上基本只有一种合理解释，指向唯一主下游对象，且不会顺带重写已有边界或引出新的核心歧义
- “不会改变多个下游依据”采用依据扇出（fan-out of support chain）口径：重点看它会不会成为多个核心判断的共同新前提
- “低风险回答”默认按是否改变事实边界与下游依据来判定，而不按内容类型粗略判定

对于回答带来的附加效果，默认还应遵守以下规则：

- 如果不改变事实边界，但会明显改变推荐倾向，则只有局部排序微调仍可视为低风险；一旦实质改变待决策候选（decision candidate）的推荐方向，就不再视为低风险
- 如果同时“消解旧冲突”又“引入新边界”，应分段处理，不能只看净效果
- 如果只是把模糊说法压成更精确表达，只有在不改变事实边界与下游依据时，才可视为低风险精化
- 如果某个解释对象（interpretation）从低置信变成高置信，但仍未形成正式边界，可以条件参与下游推进；一旦足以触发高风险对象生效，仍需补治理或确认动作

对于对象流转与关闭动作，默认还应遵守以下规则：

- 如果一个回答同时影响多个解释对象（interpretation），只有在它们共享同一语义核且不会分叉出不同下游路径时，才允许条件并行更新
- 如果旧待澄清项（clarification）可以关闭，但又自然暴露出下一层新的待澄清项（clarification），允许条件闭环；若新项其实说明旧项并未真正解决，则旧项不应关闭
- 如果一个回答只解决了旧待澄清项的一部分，应优先判断旧项是否本来混入了多个缺口；若是，则拆分处理；若不是，则不关闭，只更新进度或置信状态

#### 解释对象升级为约束的治理门槛摘要

为便于实现与后续引用，解释对象（interpretation）升级为约束（constraint）可先采用以下混合门槛：

- 当前解释对象（interpretation）已经达到较高稳定度
- 它表达的是事实性边界，而不是一般理解或偏好
- 它已经开始对后续判断形成明确边界作用
- 当前没有未处理的关键冲突在直接打它的底层依据

其中：

- “较高稳定度”默认采用条件高稳口径：
  - 默认要求高置信
  - 但如果它刚刚被一个新回答推高，且还没有经过回看或交叉检验，就不直接视为较高稳定度

- “回看或交叉检验”默认采用条件双检：
  - 最低先回看解释对象（interpretation）与来源片段（source fragment）的对应关系
  - 如果它已经开始影响其他核心对象，再额外检查它是否撞上已有约束（constraint）或待决策候选（decision candidate）

- 对偏好型内容默认采用条件分流：
  - 如果表达的是“更偏向怎样”，默认不升为约束（constraint）
  - 这类内容应优先留在解释对象（interpretation）层，或转入待决策候选（decision candidate）
  - 只有当这个“偏好”已经被明确表述为必须遵守的边界时，才可能转入约束（constraint）

- 对单一来源片段（source fragment）支撑的边界判断，默认采用条件单源：
  - 单一来源不自动等于不够
  - 关键看这个来源是否足够明确、稳定、直接
  - 但只要它会形成高影响边界，就应提高治理门槛，而不是只看来源数量

- 如果某个解释对象（interpretation）会同时压缩多个待决策候选（decision candidate）的空间，则默认采用条件升格：
  - 如果它只是压缩可选空间，而没有替代拍板动作，可以升为约束（constraint）
  - 但只要它已经实质重写多个待决策候选（decision candidate）的推荐方向或结论，就不应直接升级

#### 解释对象分流到约束 / 待决策的规则摘要

为便于实现与后续引用，解释对象（interpretation）从中间理解层分流到约束（constraint）或待决策候选（decision candidate）时，可先采用以下基线：

- 不只看它是否稳定
- 也不只看它是否影响范围大
- 关键看它表达的是“已成立边界”，还是“仍待完成的选择”

默认判断顺序是：

- 如果核心问题是“边界已成立，后续应在此内推进”，优先考虑约束（constraint）
- 如果核心问题是“仍需在多个可行方向里完成选择”，优先考虑待决策候选（decision candidate）

其中：

- 如果一个解释对象（interpretation）表达的是“偏向 A，但 B 也可行”，默认采用条件分流：
  - 只要“A”还只是当前推荐倾向，而不是已成立边界，就优先升待决策候选（decision candidate）
  - 只有当“B 也可行”其实已经不成立，或“A”已经被明确界定为必须遵守的边界时，才考虑约束（constraint）

- 如果一个解释对象（interpretation）表达的是“必须先定 X，后面才能继续”，默认采用条件判断：
  - 如果这是流程依赖，且 X 本身仍需选择，就优先升待决策候选（decision candidate）
  - 如果这是事实边界已经成立、后续只能在此内推进，才考虑约束（constraint）

- 如果一个解释对象（interpretation）已经影响多个下游对象，但这些影响本质上都围绕同一个选择展开，默认采用条件主轴：
  - 不按影响对象数量决定
  - 只要共同主轴仍然是“还要选”，就仍应优先升待决策候选（decision candidate）

- 如果一个解释对象（interpretation）同时包含“边界判断”和“选择判断”，默认采用条件拆分：
  - 如果这本来就是两个核心判断，就应拆开
  - 只有当“边界”和“选择”只是同一核心判断的不同表达层时，才允许先不拆

### 约束（constraint）

进入已确认工作事实（confirmed working truth）前必须满足：

- 有来源
- 无关键未解决冲突，或冲突已被显式记录
- 满足验证要求
- 必要时经过确认

此外，约束（constraint）默认只接收事实性边界，不接收一般偏好。

偏好（preference）当前阶段不建议做成一级主对象，而应先作为解释对象或待决策对象中的轻量字段存在。

约束最小应包含：

- 约束内容
- 依据
- 影响范围

约束一旦形成，默认稳定；只有在用户明确否认，或出现更高优先级 / 更强依据的新信息时，才允许被推翻。

#### 约束的最小治理基线

为便于实现与后续引用，约束（constraint）当前可先采用以下最小治理基线：

- 最小字段集包括：
  - 约束内容
  - 依据
  - 影响范围
  - 稳定性来源
  - 当前是否存在复核风险

其中：

- 约束内容默认采用“边界句 + 适用对象”：
  - 不只说明边界是什么
  - 也说明它约束的是哪个对象或哪个主题面

- 依据默认采用“依据摘要 + 上游对象”：
  - 既说明为什么当前可以形成这条约束（constraint）
  - 也说明它主要建立在哪些上游对象之上

- 影响范围默认采用“影响对象 + 影响方向”：
  - 不只说明它影响哪里
  - 还要说明它具体往哪个方向施加边界作用

- 稳定性来源默认采用“来源类型 + 简短说明”：
  - 不只说明它为什么稳定
  - 也说明它是怎么稳定下来的

- 复核风险默认采用“布尔值 + 关键标记”：
  - 默认只记“有 / 没有”
  - 只有当它已经足以影响下游继续把这条约束（constraint）当稳定边界使用时，才额外挂关键标记

### 决策（decision）

进入稳定事实层前必须满足：

- 明确是待决策对象或已裁决对象
- 有足够上下文支撑
- 经用户或明确授权角色拍板

待决策候选（decision candidate）既可以是多方案待选，也可以是单方案待确认。

其最小结构至少应包含：

- 待决策内容
- 可选项
- 推荐倾向
- 影响

已确认决策（confirmed decision）一旦形成，默认作为正式事实边界进入后续流程，除非被明确推翻。

它与约束（constraint）的核心区别在于：

- 约束来自已成立边界
- 已确认决策来自已完成选择

#### 待决策候选的最小治理基线

为便于实现与后续引用，待决策候选（decision candidate）当前可先采用以下最小治理基线：

- 最小字段集包括：
  - 待决策内容
  - 可选项
  - 推荐倾向
  - 影响
  - 当前依据

其中：

- 可选项默认采用条件补全：
  - 默认优先只收显式选项
  - 只有在少一个最小对照项就会导致待决策失真时，才允许补全
  - 补全项必须显式标明：它不是用户已确认选项，而是为保持决策结构完整而补出的最小对照项

- 推荐倾向默认采用“方向 + 简短理由”：
  - 不只说明当前更偏哪一项
  - 还要说明当前为什么更偏这项

- 影响默认采用“影响对象 + 影响方向”：
  - 不只说明它会产生影响
  - 还要说明它会影响谁、往哪个方向影响

- 当前依据默认采用“依据摘要 + 关联上游对象”：
  - 既说明当前为什么会形成这个待决策
  - 也说明它主要建立在哪些上游对象之上

#### 已确认决策对象本体的最小治理基线

为便于实现与后续引用，已确认决策（confirmed decision）作为对象本体，当前可先采用以下最小治理基线：

- 最小字段集包括：
  - 决策内容
  - 已确认选项
  - 确认来源
  - 影响范围
  - 当前稳定状态

其中：

- 决策内容默认采用“决策句 + 适用对象”：
  - 不只说明确认了什么选择
  - 也说明这个决策作用在哪个对象或哪个主题面上

- 确认来源默认采用“确认类型 + 简短说明”：
  - 不只说明它通过什么方式被确认
  - 也说明这次确认是如何成立的

- 影响范围默认采用“影响对象 + 影响方向”：
  - 不只说明它影响什么
  - 也说明它往哪个方向影响后续对象或推进路径

- 当前稳定状态默认采用“状态与使用模式分离”：
  - 对象状态默认只记：
    - 稳定
    - 待复核
  - “带复核保留的继续使用”不并入对象状态，而作为待复核下的一种使用模式单独表达

#### 已确认决策的回退与待复核基线

为便于实现与后续引用，已确认决策（confirmed decision）在被后续信息动摇时，可先采用以下基线：

- 已确认决策（confirmed decision）默认稳定，不因一般新信息自动回退
- 只有在出现更强依据、更高优先级边界，或用户明确推翻时，才进入回退评估
- 默认先回退到待复核状态，而不是立刻退回待决策候选（decision candidate）

其中：

- “更强依据”默认采用证据强度混合判断：
  - 不只看来源数量
  - 也不只看是否更直接
  - 而是综合看它是否更贴近原始边界、更明确、更少解释跳跃、且更能直接改写当前决策成立的依据链

- 待复核状态默认采用条件显式：
  - 默认先作为治理层状态存在
  - 但只要已经影响下游是否还能继续使用该已确认决策（confirmed decision），就必须显式暴露出来

- 待复核后的生效方式默认采用条件降级：
  - 如果复核触及核心边界或核心依据，默认暂停它作为稳定前提继续使用
  - 如果只触及外围说明或局部影响，可以保留有限生效，但必须带待复核标记

- “外围说明或局部影响”默认采用条件外围：
  - 不能只看主结论字面是否没变
  - 还要同时确认它没有改写：
    - 决策对象本身
    - 适用范围
    - 下游主要动作

- 如果用户在待复核期间明确要求“先按原结论继续推进”，默认采用条件继续：
  - 可以继续推进
  - 但必须明确这是“带复核保留的继续使用”
  - 不能重新伪装成完全稳定的已确认决策（confirmed decision）

- 如果复核完成后只需局部修订，默认采用条件修订：
  - 如果只是外围说明、适用范围微调或非核心影响修订，可以保留原已确认决策（confirmed decision）身份并记录修订
  - 但只要已经改写决策对象本身、核心适用范围或下游主要动作，就应生成新的已确认决策（confirmed decision）

#### 约束与已确认决策的并存、冲突与替代基线

为便于实现与后续引用，当约束（constraint）与已确认决策（confirmed decision）围绕同一主题同时存在时，当前可先采用以下最小治理基线：

- 默认由约束（constraint）提供上位边界
- 当已确认决策（confirmed decision）明确是在该边界内完成的具体拍板时，下游可优先引用决策对象
- 但不得脱离其上位约束语境单独使用

其中：

- 对“谁是下游主前提”，默认采用条件主前提：
  - 如果当前真正要被下游执行的是某个具体选择，且该选择并未改写上位边界，则可优先引用已确认决策（confirmed decision）
  - 如果当前真正要交代的是边界本身，或该边界正在决定下游可否继续推进，则应优先引用约束（constraint）

- 对“新决策与旧约束看起来冲突”，默认采用异常冲突：
  - 不得静默认为新决策自动推翻旧约束
  - 也不得把两者同时保留为并列有效而不做治理解释
  - 必须显式进入待复核 / 待裁决状态，再决定是约束失效、决策降级，还是对象重写

- 对“冲突期间先保护谁的稳定性”，默认采用旧边界优先：
  - 默认优先保护旧约束（constraint）的生效地位
  - 同时显式挂出“新决策冲突提案”，避免新信息被静默吞掉
  - 在复核完成前，不得把该新决策继续伪装成完全稳定的正式事实边界

- 对“复核完成后确认旧约束已被替代”，默认采用保留历史：
  - 不直接删除旧约束（constraint）
  - 保留其历史记录并标记为失效
  - 再由新的约束（constraint）或新的已确认决策（confirmed decision）接管当前生效位

- 对“新约束与新已确认决策谁接主位”，默认采用核心判断优先：
  - 不按对象类型机械抢位
  - 由当前真正要被下游执行的核心判断接主位
  - 另一方作为其上位边界或配套结果保留

- 对“替代关系是否需要对下游可见”，默认采用主视图轻显式：
  - 主视图默认先展示当前生效结果
  - 但必须保留清楚的“由谁替代谁”的可见追溯入口
  - 若属于高风险场景，可前置显示替代提示
