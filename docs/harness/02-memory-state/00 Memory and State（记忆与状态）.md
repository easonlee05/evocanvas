# Memory and State（记忆与状态）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 分组目的

本组同时放置“记忆”和“状态”，但二者不是同一概念。

- 记忆（memory）回答：系统过去沉淀了什么，哪些可以被再次带入。
- 状态（state）回答：当前工作面里哪些对象处于什么状态，下一步能否推进。

在 EvoCanvas 1.0 中，这一组文档服务的是 `Vibe Shaping` 之后的持续工作面：

```md
感觉接入 -> 对话塑形 -> 结构收敛 -> 画布显影 -> 结构化交接
```

也就是说，系统不仅要记住“用户说过什么”，还要记住：

- 哪些感觉已经被塑形成可讨论对象。
- 哪些输入已经成为证据、问题、待澄清、约束或待决策。
- 哪些内容已经确认，哪些仍然悬着。
- 当前画布、活跃缺口和交接物分别投影了什么状态。

## 2. 边界声明

记忆不等于上下文，状态不等于页面显示。

- 记忆是可复用历史资产。
- 状态是当前收敛进度和对象生效情况。
- 画布只是状态的显影层，不是事实来源本身。
- 系统挂件只是状态投影，不是独立事实源。

进一步区分：

- 记忆保存“过去有哪些可追溯材料、对象和稳定判断”。
- 状态账本保存“对象如何变化、为什么变化、还有什么未决”。
- 交接物保存“哪些状态已经足够给下一位人或下一轮 AI 继续推进”。

## 3. 这一组的核心结论

EvoCanvas 不能把聊天记录当记忆，也不能把卡片位置当状态。

主工作面应以结构化对象为中心：

1. 原始输入和来源片段提供追溯基础。
2. 卡片承接正式业务对象的显影和操作。
3. 状态账本记录对象状态、确认来源、未决和过时关系。
4. Active Todos 只从当前活跃卡片投影缺口。
5. 结构化交接物只吸收足够稳定、且保留未决边界的状态。
