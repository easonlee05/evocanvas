# L3 基线（L3 Baseline）

> 当前成熟度层级：`L3 可指导实现的治理规格层`
> 编码门槛：`本文件用于汇总 L 层当前可直接指导实现的设计禁令、最小落地要求与主干摘要`

本文件集中保存 L 层在当前阶段已经收稳的实现边界，便于后续切换到验证层（verification）、治理层（governance）或实现设计时直接引用。

## 设计禁令

L 层当前至少保留以下禁令：

- 不允许在存在明显缺口时直接输出稳定结论
- 不允许把交接物（handoff）当作任何阶段都能随手生成的总结
- 不允许把大量未确认内容堆叠后仍包装成正式交接物（formal handoff）
- 不允许在单条交接内容中混写多个可独立成立的主判断
- 不允许让高影响动作一路自动推进到底
- 不允许用“对话顺畅”替代“状态正确”

## 1.0 最小落地要求

EvoCanvas 1.0 的 L 层至少要做到：

- 明确的五段主流程
- 阶段推进器作为主调度中心
- 以“阶段节点 + 阶段内检查点”作为推进单位
- 检查点未通过时，默认停留当前阶段并优先补充不确定性显影
- 高影响动作通过门禁裁决器拦截，而不是只靠阶段内重判
- 状态账本保存最小可解释推进状态，而不是只保留阶段标签
- 交接物（handoff）依赖已有对象结构生成，而不是自由总结
- 复杂回合可选启用三角编排，但不替代主阶段骨架

## 当前已收稳的 L3 主干摘要

为便于后续切到 `V层（验证）`、`G层（治理）` 或其他层时直接引用，当前 L 层已经收稳的模块级 L3 主干可压缩为以下 10 条：

1. `L层（生命周期与编排）` 定义的是运行时收敛骨架，不是界面流程，也不是通用工作流（workflow）引擎。
2. L 层主调度中心是 `阶段推进器`；主生命周期采用五段主流程，推进单位固定为 `阶段节点 + 阶段内检查点`。
3. 主链口径采用 `线性主链 + 相邻阶段回流`；默认先停留当前检查点，不把局部问题直接放大成跨段大回退。
4. 阶段内检查点的综合判定顺序固定为：先看不确定性处理状态，再看信息充分性，最后看对象完备度。
5. `门禁裁决器` 不是第二主链，而采用 `事件触发为主 + 正式交接前固定门禁位` 的双层挂载。
6. `改变事实边界` 是最强事件触发条件；`关闭关键未决` 只有在会改写事实边界，或会改变交接主表达时，才条件触发门禁。
7. `交接主表达` 当前只限于 `主结论`、`主边界`、`主风险`；其中 `主风险` 只限于 `核心阻断风险`、`高概率失真风险`、`关键未决污染风险`。
8. 识别到 `高概率失真风险` 时，L 层默认先在阶段内透明收敛；只有当风险已经污染事实边界或交接主表达时，才升级为事件触发门禁。
9. 当风险在当前阶段内无法继续修正时，才允许按风险来源回流：解释基础被改写时回 `输入编译（compilation）`，关键输入缺失但问题框定仍成立时回 `待澄清显影（clarification）`。
10. 回流修复后，只有在完成 `最小修复 + 风险重述 + 状态账本留痕` 后，才允许重回原检查点；修复后仍存未决默认采用 `分级落位`，而不是一律重抬或一律降格。

## 跨层使用提醒

如果后续其他层与上述 10 条发生冲突，默认应优先检查：

- 是不是把 `L层` 的推进骨架问题误写成了 `V层` 的过关标准问题
- 是不是把 `L层` 的门禁挂载问题误写成了 `G层` 的放行权问题
- 是不是把当前仍应停留 / 回流的问题，提前包装成了交接或已确认事实问题
