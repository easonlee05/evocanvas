# 来源验证（Source Verification）

## 1. 来源验证回答什么

来源验证回答的是：

`这个判断站不站得住`

它检查的不是措辞是否顺，而是判断是否有足够来源、证据链和冲突披露支撑。

## 2. 来源验证的默认检查项

来源验证至少检查：

- 是否存在明确来源引用
- 是否存在可追溯证据链
- 是否还有未处理的关键冲突
- 是否能解释为什么进入当前层级或状态

只要这些条件中存在关键断裂，就不能把当前结果包装成稳定内容继续下游依赖。

## 3. 对来源片段与解释对象的额外约束

来源片段（source fragment）需要额外验证：

- 是否只是标准化摘录，而不是语义重写
- 是否保留了足够上下文，避免被断章取义

解释对象（interpretation）需要额外验证：

- 是否能回指一个或多个明确来源片段
- 是否只承载一个核心判断
- 是否把低置信解释误包装成正式结论

来源验证的关键目标，是防止“看起来像理解，实际上已经脱离依据”。

## 4. 对关键场景的来源要求

待澄清项（clarification）应能说明：

- 它与哪条证据、哪处冲突或哪块缺口有关

约束（constraint）应能说明：

- 它基于什么已成立边界
- 当前是否仍有关键冲突未披露

待决策候选（decision candidate）应能说明：

- 这不是事实边界，而是仍待选择的问题
- 当前推荐不是无来源偏好

结构化交接物（structured handoff）应能说明：

- 关键结论来自哪些上游结构化对象
- 哪些内容仍然只是高置信未确认
- 哪些未决会影响下游继续推进

## 5. 来源验证失败后的默认去向

来源验证失败时，默认不直接报“对象无效”了事，而应优先给出更保守的建议去向：

- 补充来源或补证据链
- 回到待澄清项（clarification）
- 将当前结果降级为提案（proposal）
- 在高影响场景下等待确认
