# Projection Signals（显影提示）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

显影提示回答：一次收敛回合实际更新结构化状态后，用户如何低打扰地知道画布发生了变化。

它不是每轮 Chat 的固定回复，不是另一张变化回执卡，也不承担用户确认职责。完整的状态差异、原因和回放信息属于 trace 与状态账本。

## 2. 前台默认表达

画布卡片是结构化状态变化的主要表达：

- 新增、更新或失效的对象直接在画布中显影。
- 用户可以通过卡片看到当前状态、来源和关联关系。
- 用户的追问、比较和确认仍在 Chat 中完成，而不是通过显影提示完成。
- 已澄清或已关闭的待澄清卡退出主画布默认视图和 Active Todos，但仍可通过历史与关系追溯；重新打开后恢复显影。
- 已决定的待决策 / 方案承接卡退出 Active Todos，但继续作为稳定决策结构保留在主画布默认视图，直至被重新打开、替代或归档。

发生实际变化时，系统可以显示低打扰 Toast，例如“工作面已更新”或“新增 1 个待澄清项”。Toast 只提示变化，不要求逐项解释，也不应在每轮 Chat 后固定出现。

## 3. 不产生显影提示的情况

以下情况默认不产生前台显影提示：

- Chat 回合只是讨论、追问或引导，没有结构化状态变化。
- 后置判断未触发收敛回合。
- 收敛回合过期、失败或被治理拦截，且没有改变画布状态。

这些事件仍应在 trace 中可追溯，但不应把内部运行噪音推给用户。

## 4. 与治理和可观测性的边界

- 高影响信息地位升级的确认在 Chat 中完成；Toast 不是确认入口。
- 画布是状态显影，不是事实来源或审批面。
- trace 记录本轮关联的 Chat、判断、收敛回合、对象差异、版本和时间戳。
- 状态账本记录对象为什么进入当前状态，以及仍存哪些未决。

## 5. 设计禁令

- 不允许把每轮 Chat 包装成固定变化回执。
- 不允许用 Toast 代替状态来源、治理记录或用户确认。
- 不允许因为后台任务结束就强制打断用户对话。
- 不允许创建只为解释变化而存在的前台回执卡。
