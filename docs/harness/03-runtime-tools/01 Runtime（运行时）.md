# Runtime（运行时）

> 当前成熟度层级：`L2 对象与流程定义层`
> 编码门槛：`未达到 L3，不应直接作为稳定实现规格；需继续补齐回合状态、写入锁和确认提案字段`

## 1. 这一层回答什么问题

运行时文档回答：

- EvoCanvas 的受控运行单元是什么。
- 输入编译台和右侧 AI 助手的一次推进如何执行。
- 哪些动作可以自动应用，哪些必须挂起确认。
- 并发、失败、写入和恢复如何被控制。

运行时不决定产品目标，但它必须保护 `Vibe Shaping` 的事实边界。

## 2. 受控回合

EvoCanvas 的最小运行单元不是一次模型调用，而是一次受控回合。

一个受控回合至少包含：

- 当前工作区边界。
- 当前用户输入或导入材料。
- 当前上下文快照。
- 当前意图判断。
- 当前对象提案。
- 当前风险分级。
- 当前确认请求或写入结果。
- 当前变化摘要。

因此，运行时服务的不是“让模型跑起来”，而是“让一次画布状态推进在受控边界内完成”。

## 3. 运行时设计原则

### 3.1 回合是原子推进尝试

一个回合可以：

- 完成低风险整理并写入。
- 生成高影响确认请求并挂起。
- 因输入不清晰而只追问。
- 失败并保留原输入和失败回执。

但不能进入“部分写入、部分丢失、无法解释”的状态。

### 3.2 模型输出默认是提案

模型输出不直接等于画布事实。

默认链路是：

```md
输入接收 -> 上下文装配 -> 意图判断 -> 对象提案 -> 风险分级 -> 应用 / 挂起 / 拒绝 -> 回执
```

### 3.3 写入必须区分风险

低风险整理可以自动应用，例如：

- 新增证据卡。
- 新增问题卡。
- 新增待澄清卡。
- 更新约束说明补充。
- 建立弱关系。
- 标记冲突。

高影响动作必须挂起确认，例如：

- 新建待决策 / 方案承接内容。
- 将约束卡改为已生效。
- 关闭关键待澄清问题。
- 生成或刷新交接物承接结果。
- 调整高影响推进状态或里程碑。

### 3.4 失败必须可解释

一次回合失败后，系统必须能回答：

- 失败发生在哪一步。
- 原输入是否保留。
- 哪些对象已经落盘。
- 哪些对象尚未生效。
- 是否需要人工恢复。
- 用户下一步可以怎么继续。

## 4. 受控回合生命周期

建议每次回合至少经过以下状态：

1. 已创建（created）
2. 输入已接收（input_received）
3. 上下文已装配（context_assembled）
4. 意图已识别（intent_classified）
5. 提案已生成（proposal_generated）
6. 风险已分级（risk_classified）
7. 已应用 / 等待确认 / 已拒绝（applied / awaiting_confirmation / rejected）
8. 已完成 / 已失败（completed / failed）

每个状态都应能被回执和 trace 引用。

## 5. 运行时最小约束

### 5.1 单工作区写入权

同一工作区同一时刻只允许一个事实推进型回合占用写入权。

原因：

- EvoCanvas 是收敛型工作台，不是多人实时编辑器。
- 同一主题同时推进多个高影响回合，会破坏约束、决策和交接物的一致性。

### 5.2 高影响动作必须挂起

当回合进入高影响动作确认阶段时，运行时必须生成确认请求并挂起，而不是继续向下游自动执行。

### 5.3 输入与输出都要有运行范围

运行时必须明确：

- 本回合允许读取哪些输入。
- 本回合允许修改哪些对象。
- 本回合产生哪些持久化副产物。
- 本回合是否影响 Active Todos、里程碑或交接物。

### 5.4 自动恢复必须有边界

自动重试只能用于：

- 短暂模型或工具调用失败。
- 非状态型步骤失败。
- 幂等读取失败。

自动重试不应用于：

- 已进入确认阶段的高影响动作。
- 已知存在事实冲突的对象。
- 可能导致重复写入的应用阶段。

## 6. 运行隔离模型

EvoCanvas 1.0 至少需要三层隔离：

### 6.1 逻辑隔离

以工作区为主隔离单元，保证不同主题和项目上下文不互相污染。

### 6.2 状态隔离

提案、已确认对象、交接物、快照和失败回执必须有清晰生命周期分区。

### 6.3 权限隔离

并非所有回合都拥有相同权限。

例如：

- 输入编译回合可以创建证据、问题和待澄清。
- 对话塑形回合可以追问、命名和拆解。
- 交接回合可以生成交接草稿。
- 没有任何回合可以绕过确认直接把约束标记为已生效。

## 7. 故障模型

运行时必须预先定义以下故障场景：

- 模型调用超时
- 工具调用失败
- 上下文装配失败
- 提案结构不合法
- 确认请求生成失败
- 应用阶段部分失败
- 快照或回执生成失败

对于每类故障，都应回答：

- 是否允许自动重试
- 是否需要人工介入
- 是否影响事实层
- 是否需要生成失败回执

## 8. 设计禁令

- 不允许把一次模型调用等同于完整回合。
- 不允许在无提案暂存的情况下直接写事实层。
- 不允许用“先写再说”的方式处理高影响对象。
- 不允许让失败恢复依赖人工猜测当前状态。
- 不允许因里程碑更新失败影响当前画布事实状态。

## 9. 1.0 最小落地要求

EvoCanvas 1.0 的运行时至少应满足：

- 单工作区单写入占用。
- 受控回合生命周期可记录。
- 意图、提案、风险分级、应用分阶段执行。
- 高影响动作可挂起等待确认。
- 失败时可判断是否污染事实层。
- 回执、快照和交接物具备独立生成时机和落点。
