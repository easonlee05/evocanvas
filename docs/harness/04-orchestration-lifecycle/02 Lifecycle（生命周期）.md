# Lifecycle（生命周期）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

生命周期回答：主题、回合和对象如何跨阶段演化。

它关注：

- 一个模糊感觉如何变成可讨论对象。
- 一个候选对象如何显影为卡片。
- 一个约束如何从草稿进入已生效。
- 一个待决策如何从待判断进入已决定。
- 一个交接物如何从草稿变成已确认，或在底层状态变化后变成已过时。

## 2. 三类生命周期

### 2.1 主题生命周期

主题生命周期沿 PRD 的五段旅程推进：

```md
感觉接入 -> 对话塑形 -> 结构收敛 -> 画布显影 -> 结构化交接
```

它表达的是当前主题整体走到哪里。

### 2.2 回合生命周期

回合生命周期表达一次 AI 推进的执行状态：

```md
已创建 -> 输入已接收 -> 上下文已装配 -> 提案已生成 -> 已应用 / 等待确认 / 已失败 -> 已完成
```

它表达的是本轮运行有没有完成、挂起或失败。

### 2.3 对象生命周期

对象生命周期表达卡片和交接物的业务状态。

例如：

- 待澄清卡：待提出 -> 待确认 -> 已澄清 / 已阻塞 / 已关闭。
- 约束卡：草稿中 -> 待确认 -> 已生效 -> 已替代 / 已归档。
- 待决策卡：待判断 -> 待确认 -> 已决定 -> 已归档。
- 交接物承接卡：草稿中 -> 待确认 -> 已确认 -> 已过时。

这些对象状态来自 PRD 的正式业务卡片体系，不应再被抽象“候选对象”口径反客为主。

## 3. 生命周期之间的关系

主题、回合和对象生命周期互相关联，但不能混为一谈。

- 主题进入结构收敛，不代表某个约束已经生效。
- 回合完成，不代表所有提案都已应用。
- 对象已确认，不代表整个主题可以交接。
- 交接物已确认，也可能因底层约束变化而过时。

系统挂件也参与生命周期表达，但不拥有独立事实地位：

- Active Todos 只投影当前仍影响推进的活跃缺口。
- 轻量里程碑条只提示推进位置，不替代历史版本系统。

## 4. 回流和重新打开

EvoCanvas 1.0 必须允许回流。

常见回流包括：

- 交接物暴露新冲突，回流到待澄清或待决策。
- 约束被替代，触发相关交接物过时重判。
- 待澄清回答只解决部分缺口，旧问题不关闭或被拆分。
- 用户补充新输入，回到对话塑形或结构收敛。

默认回流应优先走 `相邻语义位`，而不是动不动做跨两段大回退。

回流不是失败，而是 Vibe Shaping 中保持事实边界正确的必要动作。

## 5. 冻结、归档与过时

生命周期需要区分：

- 冻结：保留某一时点的收敛状态，用于回看或交接。
- 归档：对象不再活跃，但仍保留历史和来源。
- 过时：对象曾经可用，但底层约束、决策或来源变化后不再能安全使用。

交接物尤其需要过时判断。

## 6. 生命周期不负责什么

生命周期不负责：

- 决定具体界面布局。
- 替代状态账本记录原因。
- 替代验证器判断结构是否合格。
- 替代治理层决定高影响动作是否放行。
