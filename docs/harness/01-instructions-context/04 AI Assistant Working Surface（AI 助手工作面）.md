# AI Assistant Working Surface（AI 助手工作面）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

本文档定义右侧 AI 助手在正常 Chat 中应基于什么工作面与用户协作，以及它如何和后台收敛回合保持一致。

右侧 AI 助手是正常的 Chat 入口，但不是自由闲聊框。它持续帮助用户收敛理解，却不要求每轮直接改画布。

## 2. 右侧 AI 助手的系统角色

右侧 AI 助手的前台职责是：

1. 吸收用户输入和引用材料。
2. 帮助命名、拆解和比较模糊意图。
3. 显式指出冲突、假设和关键缺口。
4. 在 Chat 中提出追问、收敛式选项，并明确需要用户确认的产品判断与作用范围。
5. 在用户继续表达时保持对当前结构化状态的理解。

它不直接拥有结构化事实写入权。Chat 后置判断命中时，关联的收敛回合才把稳定理解整理、验证、治理并投影到画布。

## 3. AI 助手工作面的最小组成

右侧 AI 助手每轮读取：

1. 从当前结构化工作包装配出的独立 Structured Package Input。
2. 最近且相关的 `user / assistant / tool` 原始消息，其中包括本轮通过 Source Resolver 实际读取的原文结果。
3. 当前用户原样输入。

Structured Package Input 从工作包中确定性选出当前主题、对象、关系、状态、未决项、稳定内容和必要来源引用。Chat 不再把“选中卡片”“已确认约束摘要”“最近投影结果”等拆成并列事实输入；界面焦点只帮助装配器选择相关内容。

这些内容帮助 Chat 引导收敛；它们不要求模型在本轮生成卡片或固定回执。

## 4. AI 助手不应只看消息流

如果右侧 AI 助手只看消息流，而不看对象层，就可能重新打开已关闭问题、忽略当前卡片关系，或把已确认约束当成可随意改写的表达。

因此，AI 助手的工作面由基于同一权威工作包装配的 Structured Package Input 和相关原始消息构成。画布是这些状态的显影，不是额外事实来源；Chat、判断与收敛必须共用完全相同的 Structured Package Input，不得各自生成范围不同的包视图或业务摘要。

## 5. 与收敛回合的关系

Chat 回合完成后，轻量判断器会基于本轮消息和当前工作面判断是否需要启动收敛回合。

- 未触发时，Chat 继续正常引导，不产生隐形对象。
- 触发后，收敛回合独立完成提案、验证、治理和写入。
- 收敛回合实际改变状态后，画布更新；必要时显示低打扰 Toast。
- 后台回合不得以第二条 Chat 消息抢占用户，也不通过卡片要求用户确认。

## 6. 与上下文装配的关系

`Context（上下文）` 定义工作面应包含什么；`Context Assembly（上下文装配）` 定义如何装配；本文档定义正常 Chat 如何基于这张工作面持续引导用户收敛。
