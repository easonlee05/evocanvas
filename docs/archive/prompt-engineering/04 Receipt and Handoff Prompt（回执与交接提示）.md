# Receipt and Handoff Prompt（回执与交接提示）

## 1. 定位

回执 / 交接提示负责把当前结果整理成可见、可继续推进、可进入后续控制链的形式。

它更偏结果整形，而不是主流程推进。

## 2. 主要职责

回执 / 交接提示至少负责以下内容：

- 显式交代当前结果成立到什么程度
- 交代还存在哪些未决问题与边界
- 交代哪些内容只是高置信草稿
- 将结果整理成可验证、可治理、可交接的结构

## 3. 两类不同职责

### 3.1 回执提示

回执提示偏向当前回合输出的结果说明，例如：

- 本轮形成了什么
- 本轮缺了什么
- 本轮下一步建议是什么

### 3.2 交接提示

交接提示偏向面向下一位人或下一轮 agent 的结构化带出，例如：

- 当前主题
- 已稳定内容
- 未决内容
- 不可越过的边界

## 4. 当前边界

回执 / 交接提示不负责：

- 宣布验证通过
- 宣布治理放行
- 将不稳定内容包装成已确认事实

它的职责是整理结果，不是赋予结果生效权。
