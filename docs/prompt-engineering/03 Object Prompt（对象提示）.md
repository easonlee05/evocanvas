# Object Prompt（对象提示）

## 1. 定位

对象提示负责把自由生成压缩为 EvoCanvas 可治理的结构化对象。

它的重点不是让结果更像自然语言答案，而是让结果更像可继续推进的工作对象。

## 2. 最小翻译契约

对象提示当前最小应翻译三类信息：

- 当前主对象属于哪类对象
- 该对象的必备语义槽位是什么
- 哪些内容不得被越权声明为已确认、已生效或已解决

它的首要职责不是补事实，而是防止对象冒充错误地位。

## 3. 输入面

对象提示当前至少要能读取以下内容：

- 阶段提示已经选定的主对象类型
- 当前对象对应的上游素材或中间结果
- 当前对象必须保留的最小边界

它不需要也不应该自己重新判断“本轮该做哪类对象”。

如果后续写成标准模板，对象提示的输入面可以抽象成：

```text
当前主对象类型
当前对象候选内容
当前对象不得越权的边界
```

## 4. 输出面

对象提示产出的，不是“漂亮答案”，而是“像该对象的内容”。

它至少要把以下三件事做对：

- 对象身份做对
- 对象必备槽位做对
- 对象地位做对

这里的“对象地位做对”非常关键，意思是：

- 解释对象不能写得像最终结论
- 待澄清项不能写得像已解决问题
- 约束草稿不能写得像已生效约束
- 待决策候选不能写得像已拍板结果

## 5. 当前建议的对象骨架写法

这里不写 harness 层的最终结构模式（schema），只写提示层最该强制的对象语义。

当前可先采用以下最小对象骨架理解：

- 来源片段（source fragment）：回答“原始输入里到底说了什么”
- 解释对象（interpretation）：回答“当前理解成了什么，但仍可被挑战”
- 待澄清项（clarification）：回答“如果不补这件事，会卡住哪一步”
- 约束（constraint）：回答“当前不能越过什么边界”
- 待决策候选（decision candidate）：回答“当前必须拍什么板”
- 结构化交接物（structured handoff）：回答“下一位人或下一轮 AI 可以基于什么继续推进”

对象提示真正要做的，是把这些对象之间的语气、地位和边界拉开。

## 6. 与 harness 的边界

对象提示不重写对象语义基线。

EvoCanvas 1.0 当前对象范围、对象结构最小要求、来源校验与升级门槛，统一以 harness 为准。

对象提示只负责：

- 在当前回合被允许时，把对象压对

## 7. 常见失控点

对象提示最常见的失控，不是“字段不全”，而是“对象地位漂移”。

典型表现包括：

- 解释对象写成结论
- 待澄清项写成建议答案
- 待决策候选写成默认已决定
- 交接物把未确认内容直接包装成下游前提

因此，对象提示真正的价值，不是补字段，而是压住这些地位错位。

## 8. 与其他模块的关系

- 它受系统基座提示的全局边界约束
- 它受阶段提示的主对象选择约束
- 它为回执提示提供对象成立程度和降级提醒

如果当前主对象无法被压成可成立语义，当前默认采用：

- 对象提示发出降级提醒
- 但对象提示不得自行改写阶段判断

## 9. 当前边界

对象提示不负责判断：

- 这个对象现在该不该生成
- 这个对象是否已经过验证
- 这个对象是否已经获准生效
- 这个对象是否应直接进入正式交接

它只负责在被允许生成时，把对象语义做对。
