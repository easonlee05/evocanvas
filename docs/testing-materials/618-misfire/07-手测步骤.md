# 618 积分商城误杀治理：手测步骤

## 上传顺序

建议按以下顺序上传：

1. `01-问题背景.md`
2. `02-会议纪要.md`
3. `03-用户反馈.md`
4. `04-技术约束.md`
5. `05-运营诉求.md`
6. `06-待拍板问题.md`

## 推荐测试提问

### 第一轮：输入编译

```text
我刚上传了一组背景材料，请先帮我做输入编译。不要直接给方案，先提取证据、问题定义和待澄清项。
```

### 第二轮：继续澄清

```text
把当前最关键的待澄清问题列出来，尤其是一期范围、误杀成本、申诉处理和拦截粒度。
```

### 第三轮：沉淀约束

```text
基于现有信息，先把已经比较稳定的约束沉淀出来。
```

### 第四轮：形成待决策

```text
把一期到底按账号、设备还是行为会话聚合，整理成需要拍板的待决策项。
```

### 第五轮：刷新交接物

```text
整理并刷新结构化交接物草稿。
```

## 你要重点观察

1. 上传的文件有没有真正进入分析。
2. 系统是不是先暴露不确定性，而不是直接给方案。
3. `clarification`、`constraint`、`decision` 是否区分清楚。
4. 交接物里是否真的保留了待澄清、约束和待决策。
