# Governance Baseline（治理基线）

> 当前成熟度层级：`L3 可指导实现的治理规格层`
> 编码门槛：`可作为 1.0 后端状态机、Chat 确认记录和治理 trace 的设计输入`

## 1. 最小治理目标

EvoCanvas 1.0 的治理基线只做一件事：防止未收敛内容被系统误当成已成立工作事实。

这要求系统至少保证：

- 所有稳定内容都能追溯到来源、确认方式或用户裁决。
- 所有关键冲突都能被用户看见。
- 所有高影响信息地位升级都不能脱离确认依据自动生效。
- 所有结构化交接物都保留已知、未知、已决和未决。

## 2. 主路径必跑规则

每轮涉及对象写入或状态变化时，默认执行以下规则：

1. 先判断对象类型，再判断状态变化。
2. 先暴露不确定性，再沉淀约束。
3. 先识别待澄清和冲突，再生成待决策。
4. 先在 Chat 中把高影响判断及其范围聊清楚并确认，再由收敛回合验证和更新生效状态。
5. 正文变化时，结构化包新版本与状态账本在同一提交中成立；只有确认、过时或风险标注时，执行不复制正文的纯治理提交；随后再同步 Active Todos、里程碑和画布投影。
6. 交接物生成前，必须显式带出关键未决和待确认事项。
7. 清晰、完整且范围明确的用户直接陈述可以作为确认依据；含糊、保留、举例、引用他人观点或范围不明的陈述不能自动升级为确认。
8. 待澄清对象只记录缺口及其生命周期，不通过改类型承接结果；澄清后另行创建或更新关联的约束、待决策或其他结果对象。
9. 约束按“可独立确认、修改、替代或撤销”的规则边界拆分；实质语义变化创建新对象并保留替代关系，不在原对象上覆盖历史语义。
10. 用户有权确认产品内部规则；若规则所依据的是法律、平台政策、技术硬限制或数据结论等外部事实，外部事实本身仍需可验证来源。

## 3. 异常兜底规则

异常场景不应被静默吞掉。

- 输入编译失败时，原输入必须保留。
- 关系解析失败时，至少保底展示卡片本体。
- Todo 投影异常时，回退到源卡视角。
- 新输入推翻旧约束或旧决策时，旧对象不直接删除，应进入已替代、已归档或触发相关交接物过时判断。
- 用户否定或撤回建议时，拟议的高影响状态不得生效；原始 Chat 消息应保留为追溯依据。

## 4. 收敛式选项规则

AI 可以给用户收敛式选项，帮助用户更快拍板，但选项不是合法答案全集。

默认规则：

- 如果用户提出的新口径本质上重写问题边界，系统应改写当前选项面板。
- 如果用户只是对现有选项小修正，可以吸收修改并保留原结构。
- 在高风险或问题空间尚未稳定时，系统应说明选项只是当前最小比较集。
- 用户用自然语言给出明确修正时，系统应直接吸收为新基线，而不是强迫用户点选旧选项。

## 5. 最小实现清单

后端至少需要承载：

- 对象状态字段。
- 来源引用或确认方式字段。
- 高影响信息地位升级识别。
- Chat 提议、确认或否定的消息引用及其作用范围。
- 治理回执。
- 过时 / 替代 / 归档记录。
- 交接物依赖对象列表。

这些字段不要求一次做成复杂权限系统，但必须足以支撑 1.0 的确认、回退和追溯。
