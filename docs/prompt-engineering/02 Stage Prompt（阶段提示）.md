# Stage Prompt（阶段提示）

## 1. 定位

阶段提示是 EvoCanvas `prompt engineering` 的运行主控面之一。

它负责把当前回合明确绑定到 harness 已定义好的某一阶段，而不是让模型总是用同一种思路回答。

## 2. 最小翻译契约

阶段提示当前最小应翻译四类控制信号：

- 当前阶段目标
- 当前动作边界
- 当前主对象选择
- 最小回执要求

这里的“最小回执要求”当前只要求两件事：

- 本轮必须披露哪些边界槽位
- 本轮建议去向是什么

## 3. 输入面

阶段提示不是只拿到“阶段名”就够了。

它当前至少需要能读取以下四类输入：

- 当前处于哪个阶段
- 当前主题或当前工作单元是什么
- 当前回合前已经形成了哪些上游中间物
- 当前回合最需要解决的推进目标是什么

如果后续写成标准模板，阶段提示的输入面可以先统一抽象成：

```text
阶段名
当前主题
上游上下文摘要
当前回合要解决的推进问题
```

## 4. 输出面

阶段提示应产出的，不是长解释，而是一组足以约束本轮行为的控制判断。

当前至少应稳定产出：

- 这一轮的目标是什么
- 这一轮允许哪些动作
- 这一轮禁止哪些越级动作
- 这一轮主对象是什么
- 这一轮回执至少要披露什么
- 这一轮建议去向是什么

如果后续写成模板，阶段提示骨架至少应长成：

```text
当前阶段目标
允许动作
禁止动作
当前主对象
最低回执要求
默认建议去向
```

## 5. 一个好阶段提示应该长什么样

一个有效的阶段提示，不应该只是说“你现在在输入编译阶段”。

它更应该像：

- 现在这轮最重要的推进目标是什么
- 为了达成这个目标，允许模型做哪些事
- 哪些看起来有帮助、但这轮其实不能做
- 如果本轮推进失败，应该怎样保守收口

换句话说，阶段提示最核心的价值，不是“命名阶段”，而是“缩窄本轮行为空间”。

## 6. 它不直接定义什么

阶段提示不负责重新定义：

- 主阶段链
- 对象清单
- 对象升级门槛
- 验证与治理放行条件

这些内容统一以 harness 为准。

## 7. 常见失控点

如果阶段提示写得太空，最容易出现以下问题：

- 模型虽然知道自己在哪个阶段，但还是把多个阶段动作混在一起做
- 主对象没有被真正选定，导致对象提示开始自己抢控制权
- 回执输出很完整，但和本轮真正阶段目标无关

所以阶段提示最怕的不是“约束太多”，而是“知道阶段名，但不知道本轮到底该收什么”。

## 8. 与其他模块的关系

- 它受系统基座提示约束，不得覆盖系统基座规则
- 它为对象提示指定当前主对象
- 它为回执提示指定本轮最低必须带出的边界槽位和建议去向

当阶段提示与对象提示发生张力时，当前默认采用：

- 阶段提示优先
- 但对象提示可在对象压不成立时发出降级提醒

## 9. 当前边界

阶段提示负责“当前应怎么推进”，但不负责：

- 宣布对象已验证通过
- 宣布对象已获准生效
- 补写对象语义细节

这三项仍分别由验证、治理和对象提示承担。
