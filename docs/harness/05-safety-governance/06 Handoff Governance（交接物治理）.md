# Handoff Governance（交接物治理）

> 当前成熟度层级：`L3 可指导实现的治理规格层`

## 1. 这一层回答什么问题

交接物治理回答：当前画布什么时候可以收束为结构化交接物，交接物里哪些内容可以被下游依赖，哪些必须以未决或待确认形式保留。

EvoCanvas 1.0 的结构化交接物可以给同事阅读，也可以进一步派生为面向 AI 的 PRD，但它不等于传统完整 PRD，也不等于完整项目规格。

## 2. 最小内容

每份结构化交接物至少包含：

1. 当前目标。
2. 输入背景。
3. 已确认约束。
4. 已完成决策。
5. 未解决问题。
6. 待确认决策。
7. 推荐后续动作。
8. 关联当前里程碑和关键来源引用。

如果这些内容无法被稳定填充，系统可以生成交接草稿，但不能标记为已确认。

## 3. 进入交接前的检查

生成或刷新交接物前，系统至少检查：

- 关键待澄清项是否已收敛，或已显式保留为未解决问题。
- 关键约束是否已确认或明确标为待确认。
- 必要决策是否已完成，或明确列为待确认决策。
- 冲突是否已显性展示。
- 交接物引用的对象是否仍然有效。
- 交接物是否说明当前仍不能确定什么。

交接物的可读性不能凌驾于真实性之上。

## 4. 状态治理

交接物承接卡的主要状态是：

```md
草稿中 -> 待确认 -> 已确认 -> 已过时
```

治理规则：

- 草稿中：可以由 AI 生成，但只能作为工作草稿。
- 待确认：已经具备基本结构，需要用户确认。
- 已确认：可以作为后续沟通或下游 AI 输入的依据。
- 已过时：底层约束、决策或关键来源变化后，不再安全可用。

## 5. 过时判断

以下情况应触发过时判断：

- 已确认约束被替代。
- 已完成决策被撤回或重开。
- 新输入暴露关键冲突。
- 原本未解决的问题变成阻塞性交接风险。
- 当前主题目标发生变化。

过时不等于删除。系统应保留旧交接物，标记其不再适合作为当前依据，并引导用户刷新或重新确认。

## 6. 禁令

交接物治理明确禁止：

- 把聊天总结包装成结构化交接物。
- 把未确认约束混入已确认约束列表。
- 把待确认决策写成已完成决策。
- 为了让文档显得完整而隐藏关键未决。
- 在用户未确认前把交接物标记为可外发或可交给下游 AI 执行。
