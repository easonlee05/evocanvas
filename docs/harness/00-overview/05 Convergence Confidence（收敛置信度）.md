# Convergence Confidence（收敛置信度）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

本文档定义 EvoCanvas 如何判断收敛回合**内部**是否适合继续压缩问题空间。

> **范围说明：** 本文档回答的是「回合内是否适合继续向稳定结论压缩」，不是「Chat 结束后是否启动收敛回合」——后者属于触发判断，见 [Main Runtime Loop §4](./03%20Main%20Runtime%20Loop%EF%BC%88%E8%BF%90%E8%A1%8C%E4%B8%BB%E9%93%BE%EF%BC%89.md)。两者串行：触发判断先决定是否开门，收敛置信度在门内决定走多深。

这里的收敛置信度，不是”模型自我感觉良好分数”，而是系统对当前结构稳定度的综合判断。

## 2. 为什么需要收敛置信度

EvoCanvas 的主目标不是尽快生成答案，而是减少需求失真。

在 `Vibe Shaping` 语境下，这意味着系统不能因为用户表达得像一句结论，就误判为已经完成收敛。

因此系统需要判断：

- 现在是在继续接住感觉和塑形，还是已经可以沉淀约束。
- 当前内容适合形成待决策，还是仍应保留为可挑战提案。
- 此刻生成交接物是在帮助推进，还是在过早冻结。

## 3. 判断来源

收敛置信度不应完全由 AI 自评，也不应完全由死规则决定，而应采用混合机制：

- 规则层负责给出底线判断。
- AI 负责在有限范围内做局部微调。

当规则层与 AI 判断冲突时，应采用分级否决：

- 低风险对象允许 AI 在有限范围内推动继续收敛。
- 高风险对象由规则层保留最终否决权。

**对象风险分级（影响收敛置信度判断的保守程度）：**

| 对象类型 | 风险级 | 收敛保守度 |
| --- | --- | --- |
| 约束、交接包版本 | 高风险 | 无确认信号时默认保守，规则层保留否决权 |
| 待决策 / 方案承接 | 中风险 | 可提案，但规则层保留否决权 |
| 证据、问题、待澄清 | 低风险 | AI 可在验证通过后继续推进 |

## 4. 低置信度时的系统行为

**保守模式触发条件：** 满足以下任一条件时进入保守模式：

1. 压缩目标包含高风险对象（约束 / 交接包版本），且 Chat 中无明确确认信号。
2. 当前作用域内存在尚未处理的活跃冲突，且会被本次压缩影响。
3. 压缩目标对象的来源链不完整（`validation_state = warning / invalid`）。
4. 当前 Active Todos 中有 ≥ 2 个关键待澄清尚未关闭，且与本次压缩直接相关。

不满足任何一条时，AI 可以在验证通过后继续推进收敛。

进入保守模式后：

- 增强风险提醒。
- 不主动压缩为稳定结论。
- 优先补待澄清问题、冲突和缺失来源。
- 只有在用户再次明确要求推进时，才允许输出带风险标记的可推进草稿。

## 5. 高置信度不等于自动生效

即使收敛置信度较高，也不意味着对象可以自动进入事实层。

系统仍需区分：

- 是否通过结构验证。
- 是否满足来源与追溯要求。
- 是否触发高影响治理动作。

因此，收敛置信度解决的是“适不适合继续推进”，而不是“能不能直接算数”。
