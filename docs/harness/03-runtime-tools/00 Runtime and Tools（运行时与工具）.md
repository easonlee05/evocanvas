# Runtime and Tools（运行时与工具）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 分组目的

本组同时放置“运行时”和“工具”，但二者不是同一概念。

- 运行时（runtime）回答：一次 AI 推进如何在受控边界内执行、挂起、失败和恢复。
- 工具（tools）回答：输入、解析、检索、抽取、打包等外部能力如何接入系统。

在 EvoCanvas 1.0 中，这一组主要服务两个入口：

1. 输入编译台：把多源材料编译为结构化候选对象。
2. 右侧 AI 助手：把自然语言持续编译为受控画布变化。

## 2. 边界声明

运行时是执行容器与状态边界；工具是能力接入面。

- 工具成功返回不等于事实已确认。
- 运行时完成一次调用不等于状态可以生效。
- 工具结果必须进入来源、证据、提案和治理链路。
- 高影响动作必须通过确认提案，而不是由工具或模型静默落盘。
- 失败恢复必须保护原输入和已确认状态，不应为了“继续生成”而填平缺口。

## 3. 这一组的核心结论

EvoCanvas 的运行时不是“模型调用器”，工具也不是“给模型更多手”。

它们共同保证：

1. 输入能够被接住，而不是丢失。
2. 模型输出先成为提案，而不是事实。
3. 工具结果先进入来源和证据链，而不是结论。
4. 低风险整理和高影响写入被分开。
5. 每轮推进都有回执、状态和失败恢复路径。
