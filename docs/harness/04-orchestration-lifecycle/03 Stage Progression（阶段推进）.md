# Stage Progression（阶段推进）

> 当前成熟度层级：`L2 对象与流程定义层`
> 编码门槛：`未达到 L3，不应直接作为稳定实现规格；需继续补齐阶段状态字段和检查点规则`

## 1. 这一层回答什么问题

阶段推进回答：

- 当前主题处于哪一个产品阶段。
- 下一步允许往哪里走。
- 当前是否应停留、追问、显影、确认或交接。
- 若不能继续推进，应回流到哪里。

## 2. 五段产品阶段

EvoCanvas 1.0 的外层产品旅程是：

```md
感觉接入 -> 对话塑形 -> 结构收敛 -> 画布显影 -> 结构化交接
```

其中 `结构收敛` 内部展开为：

```md
输入编译 -> 待澄清问题 -> 约束 / 待决策 -> 结构化交接物
```

阶段推进必须同时理解这两层关系：产品体验从感觉开始，治理闭环从输入编译开始。

当前推进单位先固定为：

`阶段节点 + 阶段内检查点`

也就是说，系统不只判断“现在在哪一段”，还要判断“这一段当前是否允许继续前推”。

## 3. 各阶段职责

### 3.1 感觉接入

目标：

- 接住一句感觉、一段临时想法、关键词、聊天摘录、语音转写、截图说明或已有材料。
- 识别输入更像 vibe、事实材料、问题表达、方案想法、约束线索还是待决策线索。

不应做：

- 要求用户先写完整需求。
- 直接生成稳定方案。

### 3.2 对话塑形

目标：

- 复述理解。
- 帮用户命名模糊感觉。
- 拆解为问题、证据、假设、约束线索和候选方向。
- 对关键缺口主动追问。

不应做：

- 不经追问就把模糊表达落成高影响对象。

### 3.3 结构收敛

目标：

- 从输入中提取事实、问题、冲突和缺口。
- 生成待澄清项、约束候选或待决策候选。
- 显性化冲突，不静默合并。

不应做：

- 把候选约束写成已生效约束。
- 把待决策写成已决定结果。

### 3.4 画布显影

目标：

- 当候选对象具备基本语义边界、来源线索和归属栏目时，将其显影为卡片、关系、冲突提示、依赖提示和活跃缺口投影。

不应做：

- 把不稳定内容强行显影为稳定对象。
- 让 Active Todos 成为独立事实源。

### 3.5 结构化交接

目标：

- 打包当前目标、输入背景、已确认约束、已完成决策、未决问题、待确认决策和推荐后续动作。

不应做：

- 抹平未决问题。
- 把交接物写成完整传统 PRD。
- 绕过用户确认宣布可外发。

## 4. 默认检查点

每个阶段至少有一个推进检查点，首要职责不是“生成更多内容”，而是判断当前是否具备升级条件。

默认综合判定顺序是：

1. 先看关键不确定性、关键缺口和显性冲突是否已被处理到可继续推进。
2. 再看来源线索和对象归类是否已经足够成立。
3. 最后看当前动作是否涉及高影响状态变化或交接门禁。

这意味着“对象已经长出来”并不等于可以升级；若关键缺口仍在，默认应停留或回流。

## 5. 阶段切换条件

### 4.1 感觉接入 -> 对话塑形

当系统已经接住输入，并能给出可被用户纠正的理解摘要时，进入对话塑形。

### 4.2 对话塑形 -> 结构收敛

当模糊感觉已经初步形成可讨论对象，且可以提取问题、证据、缺口或约束线索时，进入结构收敛。

### 4.3 结构收敛 -> 画布显影

当结构化候选对象具备以下条件时，进入画布显影：

- 基本语义边界清楚。
- 有来源线索。
- 能归入合法栏目。
- 当前风险不要求继续追问。

这里的“进入画布显影”不只包括卡片出现，也包括：

- 栏目归属成立。
- 轻量关系可以落图。
- 冲突提示和依赖提示可见。
- Active Todos 可以从已显影对象安全投影。

### 4.4 画布显影 -> 结构化交接

当关键待澄清项已收敛、关键约束已沉淀、必要决策已完成，且当前仍未解决的问题可以被显式带出时，可以进入结构化交接。

## 6. 合法推进与合法迁移

阶段推进不只发生在 AI 自动收敛中，也发生在用户对卡片的直接操作中。

当前至少支持以下语义迁移：

1. 证据卡 -> 问题卡。
2. 待澄清卡 -> 约束卡。
3. 待澄清卡 -> 待决策 / 方案承接卡。
4. 问题卡 -> 交接物承接卡的引用输入。

其中：

- 同栏目内排序只改变展示顺序，不改变阶段语义。
- 跨栏目迁移必须是系统定义的合法落点。
- 会改变对象语义的迁移必须给出轻确认或高影响确认。

## 7. 回流规则

阶段推进不是单向流水线。

默认回流包括：

- 画布显影发现对象归属不稳，回到结构收敛。
- 结构化交接发现关键未决污染主表达，回到待澄清或待决策。
- 用户补充新输入，回到感觉接入、对话塑形或结构收敛。
- 约束或决策变化，触发交接物过时并回流重判。

如果回流只是修正局部解释或补齐一条关键缺口，默认应在原检查点重判，而不是从头重走整条链路。
