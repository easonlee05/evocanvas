# Authority and Guardrails（权限与护栏）

> 方法成熟度：`L3 可指导实现的治理规格层`
> 目标实现归属：`身份能力系统 + Tool Schema / Hooks`
> 当前实现状态：`原生权限与护栏已接入，完整验证待补齐`
> 实现说明：权限由运行时身份和能力集合注入，不能由 Prompt、模型参数或 Canvas 状态声明。

## 1. 控制目标

确保每项读取、稳定修改、交接确认和外部行动都由正确主体在正确范围内完成，并留下可审计证据。

## 2. 权限能力

最小能力集合：

```text
workspace.read
workspace.edit
workspace.confirm_semantics
handoff.confirm
source.read
source.verify
canvas.configure
external.execute:<tool>
workspace.delete
```

实际名称可调整，但读取、编辑、语义确认、交接确认、外部行动和删除必须可独立授权。

## 3. 主体规则

- Runtime 从认证上下文注入 `actor_id` 和 capabilities。
- Pi 以当前用户代理身份调用工具，但不能扩大用户权限。
- 系统自动动作使用明确 `system_actor`，只可执行确定性索引、依赖标记和投影等授权动作。
- 服务账号和外部连接必须记录其实际身份及授权范围。
- Canvas 选中态、页面角色文字或模型生成参数均不是权限证据。

## 4. 确认与权限分离

有权限不等于已确认；已确认也不等于有权限。提交和外部行动必须同时满足二者。用户直接编辑构成对该编辑的确认，但仍受 `workspace.edit` 和对象范围限制。

## 5. 高风险护栏

- Workspace 删除需要专门权限和明确目标确认。
- 外部不可逆动作需要工具级能力、动作级授权和幂等。
- 批量操作必须展示数量、范围和不可逆影响。
- 权限变更在新工具调用时立即生效；已完成效果不追溯撤销。
- 无法读取最新权限时拒绝写入和副作用，允许不敏感的普通对话。

## 6. 失败与恢复

| 原因码 | 行为 |
| --- | --- |
| `auth.identity_missing` | 拒绝需要权限的工具调用 |
| `auth.capability_denied` | 返回缺少的能力，不泄露敏感目标 |
| `auth.scope_denied` | 拒绝越界对象或来源 |
| `auth.state_unavailable` | 读操作按敏感级别降级，写和副作用关闭 |
| `auth.revoked_mid_run` | 后续工具调用重新校验并拒绝 |

## 7. 验收场景

1. 模型参数声明管理员身份不能越权。
2. 有编辑权但没有交接确认权的用户可改对象，不能确认交接。
3. 已确认外部发布但执行前权限被撤销，工具拒绝执行。
4. 系统投影账号不能调用工作包编辑接口。
5. 批量删除只确认其中一部分时，未确认范围不执行。
