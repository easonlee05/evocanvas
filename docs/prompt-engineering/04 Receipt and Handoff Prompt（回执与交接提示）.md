# Receipt and Handoff Prompt（回执与交接提示）

## 1. 定位

回执 / 交接提示是 EvoCanvas `prompt engineering` 的输出模块。

它负责把上游模块已经形成的结果，整理成可见、可继续推进、可进入后续控制链的形式。

它更偏结果整形，而不是主流程推进。

## 2. 最小翻译契约

回执 / 交接提示当前最小负责两件事：

- 把必显槽位稳定表达出来
- 对这些槽位做轻量整理

这里的“轻量整理”包括：

- 调整表达顺序
- 合并重复边界
- 把建议去向组织得更易继续推进

但不包括：

- 补写上游没有提供的事实
- 重做阶段判断
- 重写对象语义

## 3. 输入面

回执 / 交接提示当前至少要能读取以下内容：

- 阶段提示给出的最低回执要求
- 对象提示给出的对象成立程度或降级提醒
- 系统基座提示是否触发冲突覆盖
- 当前回合已经形成的结果摘要

如果进入结构化交接阶段，它还需要额外读取：

- 当前哪些内容可以作为跨回合继续推进依据
- 当前哪些边界必须继续被保留

## 4. 输出面

回执 / 交接提示当前不产出新判断，它产出的是“可见整理结果”。

这类输出至少要做到三件事：

- 让人一眼看出这轮到底形成了什么
- 让人一眼看出这轮还缺什么、哪里不稳
- 让下一步推进方向足够明确

如果后续写成标准模板，输出模块的最小骨架可以先理解为：

```text
本轮形成内容
当前未决 / 冲突 / 未确认边界
对象是否成立或是否降级
建议下一步
```

## 5. 回执态与交接态

### 5.1 回执提示

回执提示面向当前回合。

它至少应能表达：

- 本轮形成了什么
- 本轮哪些内容仍不成立或仍未确认
- 本轮有哪些未决问题、冲突边界、未确认前提与当前收敛置信度
- 本轮建议去向是什么

如果对象提示触发“对象压不成立”的降级提醒，这一信息必须作为回执必显槽位带出。

如果系统基座提示触发冲突覆盖，回执提示必须切换到标准冲突 / 降级回执表达，而不能继续沿用普通推进口径。

这意味着回执提示至少要有三种稳定口径：

- 普通推进回执：本轮有正常收敛结果
- 对象降级回执：本轮对象压不成立，但仍可继续推进
- 冲突覆盖回执：本轮被系统基座规则打断，必须保留冲突外显

### 5.2 交接提示

交接提示不是独立强主控模块，而是：

- 当阶段进入结构化交接时，回执输出向跨回合打包态的延长

它面向下一位人或下一轮 `AI`，至少应带出：

- 当前主题
- 当前已稳定或可继续依赖的内容
- 当前仍未决或仍需保留的边界
- 不可越过的前提
- 建议从哪里继续推进

交接提示最关键的，不是写得完整，而是让下游能区分：

- 哪些内容已经足够可依赖
- 哪些内容只是高价值但未确认的草稿
- 哪些内容仍然不能跨过去

## 6. 常见失控点

输出模块最常见的失控，不是排版不好，而是“整理时偷偷改写判断”。

典型表现包括：

- 回执把本轮草稿整理得像结论
- 为了让交接物更顺，把未决问题弱化掉
- 把对象提示的降级提醒消化掉，不再对外可见
- 把冲突覆盖写成模糊提醒，而不是明确打断

所以输出模块的核心纪律不是“完整”，而是“不能在整理时偷改地位”。

## 7. 当前边界

回执 / 交接提示不负责：

- 宣布验证通过
- 宣布治理放行
- 将不稳定内容包装成已确认事实
- 代替系统基座提示处理模块冲突

它的职责是整理结果，不是赋予结果生效权。
