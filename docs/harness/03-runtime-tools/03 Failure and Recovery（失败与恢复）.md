# Failure and Recovery（失败与恢复）

> 当前成熟度层级：`L2 对象与流程定义层`

## 1. 这一层回答什么问题

本文档定义一次受控回合失败时，系统如何重试、挂起、恢复和留痕。

## 2. 失败分类

至少应区分：

- 模型调用失败。
- 工具调用失败。
- 上下文装配失败。
- 提案结构不合法。
- 验证失败。
- 治理拦截。
- 应用阶段部分失败。
- 里程碑进度更新失败。
- Todo 投影异常。

## 3. 自动重试边界

自动重试只适合：

- 短暂调用失败。
- 非状态型步骤失败。
- 幂等工具读取失败。

自动重试不适合：

- 已进入用户确认的高影响动作。
- 已知存在事实冲突的对象。
- 可能导致重复写入的应用阶段。
- 已生成确认提案但用户尚未处理的动作。

## 4. 恢复要求

每次失败后，系统至少要能回答：

- 失败发生在哪个阶段。
- 哪些对象已经落盘。
- 哪些对象尚未生效。
- 是否需要人工恢复。
- 是否生成失败回执。

## 5. 1.0 异常处理规则

### 5.1 输入编译失败

输入编译失败时：

- 原输入必须保留。
- 系统应提示失败发生在识别、分段、抽取还是显影前。
- 用户应能重试或补充输入类型 / 背景说明。
- 不得因为编译失败而丢失用户原始表达。

### 5.2 高影响动作未确认

高影响动作未确认时：

- 不允许直接落图或改状态。
- 应保留确认请求。
- 状态账本不得把它记录为已生效。

### 5.3 卡片关系解析失败

卡片关系解析失败时：

- 应保底展示卡片本体。
- 应记录关系解析失败原因。
- 不应导致整个栏目或工作面消失。

### 5.4 Todo 投影异常

Todo 投影异常时：

- 应回退到源卡视角。
- 不得保留失效 Todo。
- 若源卡已关闭、删除或归档，对应 Todo 应同步失效。

### 5.5 里程碑更新失败

里程碑进度更新失败时：

- 不应影响当前画布状态。
- 不应阻断卡片、约束或交接物的正常显示。
- 应作为运行提醒进入回执或 trace。

## 6. 失败回执

失败回执至少包含：

1. 失败阶段。
2. 失败对象或输入。
3. 已保留内容。
4. 未生效内容。
5. 建议下一步。

失败回执的目标不是解释所有内部细节，而是让用户知道当前工作没有被悄悄污染，以及下一步如何继续。
